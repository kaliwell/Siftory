# 随包用户协议配置

当前 `manifest.json` 为 `status: "open-source"`：软件内可查看 Apache-2.0 许可与第三方适用范围说明，启动时不要求签署专有软件协议，不生成同意记录。文档仍经过路径、大小、UTF-8 和 SHA256 校验。项目不再要求购买商业授权。

正式启用前，权利人须确定发布者、条款内容、版本、生效日期及实际审批依据。将完整纯文本文件放入本目录，更新配置为：

```json
{
  "schemaVersion": 1,
  "status": "final",
  "title": "正式协议标题",
  "version": "经确定的协议版本",
  "publisher": "实际发布者",
  "effectiveDate": "2026-09-25",
  "documents": [{ "path": "EULA.zh-CN.txt", "sha256": "替换为该文件原始字节的 SHA-256" }]
}
```

以上是格式示例，日期和身份均须按实际情况确定。示例不是有效配置或授权声明。

`documents` 按数组顺序作为纯文本展示。文件名只允许目录内的英文、数字、点、横线或下划线，扩展名为 `.txt` 或 `.md`；不解析 Markdown 或 HTML，不访问链接。文件应为 UTF-8，所有正文合计不得超过 512 KiB。SDK 等第三方条款若纳入协议，必须提供完整实际文本并保留开源组件适用的权利例外，不能仅引用未随附的网页。

运行时验证各文件原始字节摘要；同意记录另以标题、版本、发布者、生效日期和拼接正文的整体摘要绑定用户看到的内容。任何一项变化都要求重新确认。条款缺失、无效或保存失败时不启动应用服务。

同意记录仅保存在应用数据目录的 `end-user-terms-acceptance.json`，含配置版本、摘要、发布者及本机时间；不收集姓名、证件号、IP 或机器标识，也不上传。它是可被本机用户修改的本地记录，不是身份核验、电子签名、软件著作权登记签署或法律有效性的证明。拒绝或关闭窗口不生成记录。

发布检查同时要求 `legal/license-decisions.json` 中经真实审批的 `project.licenseFile` 指向实际展示的某个协议文件，并要求整个目录原样随包。自动校验只能检查配置与文件一致性，不能代替权利人确定条款及其适用性。
