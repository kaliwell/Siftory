## 1. 登记范围和当前状态

自然人可以申请；应申报本人实际享有著作权的软件和文档。登记证书是登记事项的初步证据，不会取得第三方代码、模型权重、字体或运行库的所有权，也不会替代它们的使用许可。合作、委托、职务开发及继受取得需要分别核对。[《计算机软件保护条例》（2013 年修订），第 7、9—14 条](https://www.cac.gov.cn/2013-02/08/c_12648744.htm)

本地 `package.json` 是 `siftory-desktop@1.0.0`，用户已确认 Siftory／寻藏品牌。用户陈述完成日期为 2026-09-25、未发表、本人从头独立开发并完成设计及代码编写修改；没有共同开发者、职务或委托开发、权利转让或继承等情形。草稿按本人自述记录原始取得，第三方组件排除于原创主张。正式登记全称、版本、权利人真实姓名及个人材料仍待完成。完成日期取自用户明确陈述，不以文件或 Git 时间替代。`legal/commercial-release-decisions.json` 的公开主体身份和正式发布批准仍未补齐。

## 2. 准备材料

| 材料 | 准备口径 |
| --- | --- |
| 申请表 | 在中国版权保护中心系统填写，名称、版本、权利人、日期与附件一致；使用系统生成的确认签章页。 |
| 身份证明 | 本人有效身份证明清晰扫描件；准备身份证正反面，具体认证照片、文件格式和大小按本人登录后的实名页面办理。本报告不收集证件号码或照片。 |
| 源程序鉴别材料 | 一般交存为前 30 页和后 30 页的连续源程序；整个源程序不足 60 页时交全部；通常每页不少于 50 行。 |
| 文档鉴别材料 | 任取一种真实文档，如用户手册或设计说明书，同样前后各连续 30 页；不足 60 页交全部；通常每页不少于 30 行，特殊情况依办理要求。不是必须凑足 60 页。 |
| 权属证明 | 存在合作、委托、项目任务、原软件改编授权、受让或继承时，准备对应合同或证明；没有这些情形不得编造。 |
| 特殊交存 | 如需保密，可按第 12 条选择例外交存方式，或咨询第 13 条封存；不要自行大面积涂黑后按普通交存提交。 |

程序与文档分别适用页数要求，并非合计 60 页。上述材料、行数与例外交存依据为[国家版权局《计算机软件著作权登记办法》，2002-02-20 施行，第 9—13 条](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)。

建议以冻结的代码版本生成可追溯的源程序顺序和页码；登记提取主体为经权利链确认的原创程序。排除 `node_modules`、模型权重、第三方 vendored 头文件、字体、编译产物及自动生成代码等不应冒认原创的材料；选择原文件后保持连续性，不拼凑出虚构程序。界面截图应来自真实版本，不包含他人私人素材。这是本项目的材料整理建议，并非登记机关要求提交整个仓库。

## 3. 网上办理与签署

1. 从[中国版权保护中心官网](https://www.ccopyright.com.cn/)进入登记系统，选择个人账户，由本人完成实名认证。自然人选“个人”的流程可交叉核对[上海计算机软件技术开发中心办理说明](https://sscenter.sh.cn/SoftwareCopyrightAgency/index.html)；该页面的代理服务邮箱不是自行申报必须使用的渠道。
2. 填写软件登记申请并上传鉴别材料及证明；下载或在线打印系统生成的确认签章页，由本人按页面要求签名，再扫描上传。不要改动签章页的内容、格式或打印比例。[深圳市政府网站办理说明 PDF，第 103 页](https://www.sz.gov.cn/attachment/1/1500/1500482/11663811.pdf)
3. 核对后由本人提交，留存申报副本、流水号、受理通知及补正记录。2023-06-01 起实施的软件登记网上办理公告说明，材料通过系统填写、上传和提交，原则上不再交纸质材料。[湖北省版权保护与服务网转载中国版权保护中心 2023-05-25 公告](https://www.ccct.net.cn/html/bqzx/2023/0531/4368.html)
4. 持续查看受理及补正通知。法定审查期限按受理日起 60 日理解，不是从开始准备或点击提交起保证 60 日拿证；实际进度取决于受理和补正。[国家版权局登记办法，第 19—22 条](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)

本次直连 CPCC 官网及登记入口超时或未取得可读页面，未查看登录后的实时表单。上述流程以政府及版权服务机构公开资料交叉确认；实时文件大小、实名验证方式、电子签署选项和证书领取界面仍须提交前核对。[北京市投资促进服务局 2026-04-28 官方问答](https://invest.beijing.gov.cn/sy/zt/qyrx/202604/t20260428_4620302.html)确认注册、实名、填报提交、受理审查的基本流程，并给出软件登记咨询电话 010-61090099。未采用相似域名 `ccopyright.ai` 的收费、加急或时限说法。

## 4. 个人权利链记录与留证

自主开发及不存在合作、委托、职务开发和权利转移等事实已由用户回答；下表作为开发过程和来源证据的留存清单，不重复将已确认事实标为未知。AI 辅助的具体过程和引入代码来源仍应据实记录。

| 来源情形 | 待确认事实与材料 |
| --- | --- |
| 自主开发 | 谁实际编写、设计和修改哪些模块；保留历史版本、设计记录和开发过程证据。不能仅凭仓库在本人电脑上认定全部自有。 |
| 合作开发 | 是否有其他自然人或机构贡献有独创性的代码、设计或文档；核对合作协议、贡献范围、共有或转让约定，不能遗漏真实共有权人。 |
| 委托、外包、付费模板 | 是否购买开发服务或接受委托；核对书面著作权归属与许可范围。无明确归属约定的委托开发，法定默认归受托人，付款本身不等于受让全部著作权。 |
| 任职、学校或课题任务 | 是否与本职开发目标、工作结果、单位资源及责任有关；核查劳动合同、任务书、学校／科研协议和必要的权属证明。不能默认业余时间编写就一定个人所有。 |
| 继受、改编或开源代码 | 已有项目、拷贝代码、SDK 示例分别来自谁；保留许可证、转让或改编授权；分清原作与本人新增部分。 |
| AI 辅助 | 记录工具与服务条款版本、输入素材来源、可识别的第三方输出、人工选择修改与测试过程。不要把 AI 会话当作第三方权利保证，不冒认未核实的输出来源；也不把 AI 工具名虚构为自然人共同作者。具体可保护范围应根据人的实际创作事实判断。 |

合作、委托和职务开发的法定归属基础见[《计算机软件保护条例》第 10—13 条](https://www.cac.gov.cn/2013-02/08/c_12648744.htm)。申请草稿只按本人已经陈述的事实填写；如出现不同证据，应先更正，不将“全部权利”延伸至第三方组件。
