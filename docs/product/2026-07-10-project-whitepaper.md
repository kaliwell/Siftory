## 1. 执行摘要

Siftory（寻藏）已经从一个桌面浮动时钟工具，演进为一个本地优先的桌面效率与个人数据检索平台。当前项目的核心价值不再只是“显示时间”或“打开快捷方式”，而是把文件管理、图片检索、视频检索、向量语义搜索、远程终端、应用空间分析等能力整合到一个可常驻桌面的轻量工作台中。

项目当前最有商业潜力的方向是：

1. 本地 AI 素材检索：面向图片、视频、截图、设计素材、商品图、素材库的本地相似搜索和语义搜索。
2. 本地媒体知识库：把视频拆成可检索的关键帧、字幕和片段，支持以图搜视频、文本搜视频、多模态融合搜索。
3. 桌面运维工作台：面向开发者和技术用户，提供远程终端、SFTP、文件传输、应用空间分析、重复文件查找等工具。
4. 隐私优先的个人数据管理：大量检索和索引在本机完成，适合对素材、客户文件、内部视频和工作目录有隐私要求的用户。

截至 2026-08-19，工程已经从基础搜索链路继续扩展到统一数据源、稳定素材身份、统一搜索、首次运行与任务中心、视频/音频语义、播放器命中导航、专业导出和产品健康修复。最新全项目多维审计记录了完整验证、依赖审计、双语 14 面板 UI 冒烟和内部 Online 安装候选构建通过，但公开/商业发布仍被项目与第三方许可证、最终政策、代码签名、干净提交、受控质量基线和与提交绑定的安装包矩阵证据阻塞。接下来商业化的关键不是继续无限扩张功能，而是选择清晰用户群，关闭发布门禁，并验证用户是否愿意为稳定发行、专业工作流、团队能力和企业交付付费。

## 2. 产品定位

### 2.1 一句话定位

Siftory（寻藏）是一个本地优先的桌面 AI 工作台，用于管理、检索、清理和操作个人或小团队的本地文件、图片、视频、应用和远程主机。

### 2.2 产品边界

当前项目不应被定位为单一工具，而应定位为“桌面个人数据操作层”：

| 能力层 | 当前代表功能 | 用户价值 |
| --- | --- | --- |
| 桌面浮窗层 | 时钟、文件夹、提示词、计算器、多面板布局 | 常驻桌面，降低工具切换成本 |
| 文件管理层 | FileManager、Duplicate Finder、AppStorage | 找文件、清理重复、理解磁盘占用 |
| 图片智能层 | ImageSearch、fast_scanner、DINO/CLIP、语义搜索 | 找相似图、找同款、找截图、找素材 |
| 视频智能层 | MediaSearch、抽帧、字幕、帧向量、多模态搜索 | 在视频中定位画面和内容 |
| 运维操作层 | RemoteTerminal、SFTP、Transfer | 管服务器、传文件、执行远程工作 |
| 工程安全层 | IPC contract、path guard、safeStorage、测试链 | 支撑产品化和商业交付 |

### 2.3 差异化方向

Siftory（寻藏）的差异化不是单点算法，而是本地桌面整合：

- 相比普通文件管理器：增加图片/视频/语义检索能力。
- 相比云盘或在线素材库：数据本地索引，隐私压力更低。
- 相比单独图片搜索工具：同时覆盖图片、视频、重复文件、应用空间和远程终端。
- 相比专业 DAM 或 MAM 系统：部署轻量，适合个人、创作者、小团队和离线环境。
- 相比纯 AI 聊天产品：直接连接本地文件、视频、图片和桌面工作流。

## 3. 当前项目进度

### 3.1 工程状态

截至 2026-08-19，项目在 2026-07-10 的基础工程化工作之上，已经形成以下主链：

- 主进程入口职责收敛，核心 IPC 已迁移到按领域拆分的 `*Ipc.ts` 模块。
- `shared/ipc-contract.ts` 已开始领域拆包，MediaSearch 类型已迁移到 `shared/ipc/media-search.ts`。
- ImageSearch、MediaSearch、RemoteTerminal、AppStorage、DuplicateFinder 已 lazy load，降低首屏负担。
- 新增 `panelRegistry`，大面板 lazy loader、可见性 key、错误边界名、预加载顺序集中配置。
- 新增 `modelRegistry`，集中管理 DINO/CLIP 的维度、子进程入口、默认后端和能力标签。
- 加强 path guard 和 shell path wrapper，降低本地文件打开能力滥用风险。
- RemoteTerminal profile 增加 normalize/validate，限制异常 host、port、id、密钥路径等字段。
- `safeEval` 已移除动态执行，改为手写表达式 parser。
- MediaSearch 结果帧图已改为按需懒加载，避免批量 data URL 通过 IPC 造成卡顿。
- Frame index 增加 meta 文件，用 source signature 判断索引新鲜度。
- benchmark、native 产物治理和 IPC capability matrix 文档已补充。
- 本地盘、移动盘、NAS/SFTP 等来源进入统一来源目录，使用稳定素材身份和分阶段索引状态支撑统一搜索。

- 统一搜索结果支持证据解释、本地相关性反馈、播放器命中导航、JSON/CSV、CMX3600 EDL 与 FCPXML 导出。

## 4. 当前产品能力详解

### 4.1 桌面浮动工作台

Siftory（寻藏）的基础体验是常驻桌面的多面板系统。它包含时钟、文件夹快捷入口、提示词、设置、计算器、文件管理器、图片搜索、应用空间分析、远程终端、重复文件查找和媒体搜索等面板。

商业意义：

- 降低工具切换成本，让产品保持高频可见。
- 多面板布局适合重度桌面用户、开发者、素材管理人员。
- 浮窗形态可以作为后续插件、工作流和 AI 助手入口。

### 4.2 ImageSearch 图片检索

ImageSearch 已经从简单图片查找升级为多层检索系统：

- 第一层：fast_scanner native addon，支持 DiffHash、DCT、segment、mmap 等高性能近重复检索。
- 第二层：DINO/CLIP embedding，支持跨背景、跨构图的视觉相似召回。
- 第三层：颜色、形状、语义等精排方向已经具备基础。
- 支持剪贴板图片、查询图片、语义搜索、分层搜索、native correctness 测试。

商业意义：

- 面向电商、设计、摄影、素材库、截图管理等场景，能解决“我有一张图，但不知道文件在哪”的强需求。
- 本地索引适合隐私素材、客户图、设计稿、未发布商品图。
- 近重复和相似图能力可扩展为清理、归档、版权/素材复用检查。

### 4.3 MediaSearch 视频检索

MediaSearch 当前能力链路：

`scan video -> metadata -> thumbnail -> frame extraction -> frame embedding -> frame index -> image/text/multimodal search`

已具备：

- 视频文件扫描。
- FFmpeg / FFprobe 工具配置。
- 视频元数据读取。
- 封面缩略图缓存。
- 视频代表帧抽取。
- 帧列表可视化。
- DINO / CLIP 帧 embedding 构建。
- frame embedding 覆盖统计。
- 相似帧检索。
- 外部图片搜视频帧。
- 文本搜视频画面。
- 字幕提取、文本搜索和多模态融合。
- frame embedding 二级索引。
- 按需加载帧图，降低打开和搜索结果渲染压力。
- Qwen3-VL 视频语义候选、SenseVoice 音频语义、VAD 与单视频匿名说话人聚类主链。
- 统一搜索命中范围、查询和证据来源的受控播放器展示，以及上一处/下一处导航。
- 播放器入点/出点、逐帧精调、循环选区和 H.264/AAC MP4、CMX3600 EDL、FCPXML 导出。
- 搜索结果 JSON/CSV、EDL 和 FCPXML 批量导出，包含有界字段、路径守卫和格式验证。

商业意义：

- 视频素材、监控片段、课程录屏、会议录屏、剪辑素材、影视资料都存在“找某个画面”的痛点。
- 本地视频搜索相比云端上传更适合大文件、隐私文件和离线工作环境。
- 可演进为个人/小团队本地 MAM，即轻量 Media Asset Management。

### 4.4 RemoteTerminal 远程终端

当前具备：

- SSH profile 管理。
- 凭据安全存储。
- host fingerprint 校验。
- 远程终端会话。
- SFTP 只读浏览。
- 单文件上传/下载传输队列。
- 传输 token 绑定 renderer sender，降低跨窗口滥用风险。
- RemoteTerminal、SFTP、Transfer、Stress 测试覆盖。

商业意义：

- 面向开发者、运维、小团队技术负责人。
- 如果继续补齐自动重连、日志、分屏、命令片段、端口转发、跳板机，可以形成轻量终端工作台。
- 与文件/素材管理结合后，可覆盖“本地素材处理 + 远程服务器发布/运维”的完整工作流。

### 4.5 AppStorage 与磁盘治理

当前具备：

- Windows 应用空间分析。
- 应用路径推断。
- 目录空间估算。
- 搜索、排序、路径明细。
- 打开路径能力已走安全 wrapper。

商业意义：

- 面向普通 Windows 用户可形成“清理空间”的低门槛入口。
- 与 Duplicate Finder、FileManager 组合后，可形成桌面存储治理套件。
- 对商业版可以增加报告导出、清理建议、缓存规则、风险提示和批量治理。

## 5. 技术资产与壁垒

### 5.1 本地优先架构

项目大量能力在本机完成：

- 图片 hash 和 native 扫描。
- DINO/CLIP embedding。
- 视频抽帧和 frame index。
- 字幕解析和本地文本检索。
- 本地设置、索引、manifest、缓存。

这使产品在隐私、离线、低延迟、私有素材场景中更有价值。

### 5.2 Native + Electron 混合能力

Electron 提供跨平台桌面 UI 和快速迭代能力，native addon 提供高性能图片扫描能力。这种组合适合构建“桌面 AI 工具”，避免纯 Web 工具无法高效访问本地文件系统的问题。

### 5.3 可复用的检索底座

当前项目已经形成几类可复用底座：

- path guard 与 shell wrapper。
- IPC contract 与 preload contract test。
- task progress 模式。
- ImageSearch native scan/index 模式。
- vector embedding 子进程模式。
- MediaSearch frame index 模式。
- panel registry 与 lazy panel 模式。
- model registry 模式。

这些底座能降低后续增加 Asset Library、OCR、ASR、ANN 索引和插件系统的成本。

### 5.4 安全边界基础

当前安全基础包括：

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- preload 固定 API 暴露。
- path guard。
- safeStorage。
- host fingerprint。
- IPC 完整性测试。
- IPC capability matrix。

商业交付时，这些能力能降低客户对本地文件、远程凭据和隐私数据的顾虑。

## 7. 商业价值分析

### 7.1 价值主张

Siftory（寻藏）的商业价值可以概括为四点：

1. 节省检索时间：把“翻文件夹、翻视频、翻素材库”的人工时间变成本地索引搜索。
2. 降低隐私成本：用户不需要把私有图片、视频和客户资料上传到云端。
3. 提升素材复用率：让已有图片、视频、截图和设计稿更容易被再次找到。
4. 整合桌面工作流：减少用户在文件管理器、终端、清理工具、图片工具、视频工具之间切换。

### 7.2 可商业化模块优先级

| 优先级 | 模块 | 商业化原因 |
| --- | --- | --- |
| P0 | ImageSearch Pro | 已有基础强，用户价值直观，演示效果好 |
| P0 | MediaSearch Pro | 差异化强，能解决视频素材检索痛点 |
| P1 | Asset Library | 可把搜索能力变成长期资产管理能力 |
| P1 | Duplicate / Storage Suite | 普通用户容易理解，适合作为入口功能 |
| P1 | RemoteTerminal Pro | 面向开发者付费意愿更稳定 |
| P2 | Team / Enterprise Offline | 私有数据、本地部署、批量授权空间更大 |

### 7.3 潜在收入模式

建议采用分层授权，而不是一次性把所有能力免费开放：

| 版本 | 目标 | 功能边界 |
| --- | --- | --- |
| Free | 获客和基础留存 | 浮窗、基础文件夹、基础计算器、有限图片搜索、有限重复查找 |
| Pro Personal | 个人创作者和重度用户 | 高级图片搜索、视频搜索、批量索引、OCR/ASR、报告导出 |
| Studio | 小团队素材管理 | Asset Library、分类、标签、项目库、共享配置、批量处理 |
| DevOps Pro | 开发者/运维用户 | RemoteTerminal 高级能力、分屏、日志、命令片段、端口转发 |
| Enterprise Offline | 私有部署客户 | 离线安装包、模型包、策略配置、审计文档、企业支持 |

如果后续批准开放核心，以上分层需要从“限制社区代码功能”调整为“开放可独立使用的基础闭环，销售官方发行、专业工作流、团队/企业能力和支持责任”。真正的开源许可证允许第三方商业使用；官方版本应主要依靠商标、签名、更新、兼容质量和服务形成差异，而不是宣传无法由许可证保证的独家代码控制。

### 7.4 商业护城河

短期护城河：

- 本地图片和视频检索链路已经跑通。
- native 图片扫描性能基础较好。
- 多面板桌面工作台形态有差异化。
- 代码中已经具备安全、测试、构建和打包基础。

中期护城河：

- 素材库长期索引和用户分类数据。
- 本地多模态检索质量。
- 大数据量下的索引性能和稳定性。
- 本地隐私和离线部署体验。

长期护城河：

- 插件/模型/工作流生态。
- 团队素材资产管理。
- 跨设备或私有云同步。
- 行业模板，例如电商商品图、设计素材、视频剪辑、教育录屏、安防视频。

## 8. 未来功能规划

本节保留产品方向，但不能继续把 2026-07-10 的规划措辞直接当成当前缺口。截至 2026-08-19，首次启动、任务/健康中心、统一搜索、素材库、视频/音频语义主链、播放器导航和剪辑导出等工程功能已经实现；仍待处理的是公开/商业发布许可、真实用户与真实素材验收、跨设备团队能力、插件生态和长期支持体系。工程任务状态以[软件产品化自动优化 TODO](../current/2026-08-17-productization-auto-todo.md)为准。

### 8.1 近期功能：产品化和稳定性

这些功能优先级最高，因为它们决定能否从“工程项目”变成“可交付产品”。

| 功能 | 目标 | 商业价值 |
| --- | --- | --- |
| 首次启动向导 | 引导用户选择素材目录、模型、FFmpeg、索引策略 | 降低上手门槛 |
| 统一任务中心 | 展示扫描、embedding、抽帧、缓存、错误和暂停/恢复 | 降低长任务不透明感 |
| 索引健康面板 | 显示 manifest、frame index、embedding coverage、缓存大小 | 提高用户信任 |
| 性能预算与 benchmark | 固定输出大目录、10 万 manifest、视频索引耗时 | 支撑商业稳定性承诺 |
| GUI smoke 测试 | 覆盖主要面板打开、无白屏、无 console error | 降低发布风险 |
| 本地错误报告 | 本地 crash/log 打包导出，不默认上传 | 方便支持和调试 |
| 授权与版本能力开关 | Free/Pro/Studio 功能边界 | 商业化基础设施 |

### 8.2 ImageSearch 后续功能

建议方向：

1. ANN 向量索引：为大规模图片库提供更快的向量检索。
2. CLIP 全库文本搜图：完善 text/image embedding 构建和索引。
3. 局部区域搜索：用户框选图片局部后搜相似物品。
4. 批量相似组整理：把重复、近重复、相似主题自动聚为组。
5. OCR 文本提取：截图、海报、票据、图片文字可搜索。
6. 模型许可白名单：商业构建中只默认提供许可清晰的模型。

商业价值：

- 适合 Pro Personal 和 Studio。
- 可作为最容易演示和转化的核心卖点。
- 对电商、设计、摄影、素材库用户价值明确。

### 8.3 MediaSearch 后续功能

建议方向：

1. 真实视频样本性能审计：记录扫描成功率、抽帧耗时、检索耗时、失败原因。
2. ASR 语音转文字：引入 Whisper 或可选本地 ASR 模型。
3. OCR 视频文字识别：识别画面中的字幕、PPT、代码、标题。
4. 时间线结果视图：搜索结果按视频时间轴聚合展示。
5. 片段导出：从搜索命中的时间点快速导出片段或截图。
6. 多模态查询模板：图片 + 文本 + 字幕 + 时间范围联合搜索。
7. 视频资产库：把视频按内容、人物、场景、字幕、标签管理。

商业价值：

- 是最强差异化方向。
- 适合剪辑师、课程录屏、会议视频、知识库、监控或档案检索。
- 可作为高价 Pro / Studio 功能。

### 8.4 Asset Library / NekoSearch

建议新增独立 Asset Library 面板，而不是继续扩大 ImageSearch 面板。

核心功能：

1. 素材入库。
2. 分类树。
3. 标签系统。
4. 手动分类。
5. 参考图分类。
6. 文本标签分类。
7. 聚类自动分组。
8. 重复/近重复素材归并。
9. 未分类素材处理队列。
10. 分类建议状态机。

数据层建议：

- P0：JSONL + manifest，快速落地。
- 终态：SQLite + 向量文件/索引，支撑大库和迁移。

商业价值：

- 这是从“搜索工具”升级为“素材资产管理平台”的关键。
- 一旦用户完成分类、标签和索引，迁移成本会提高。
- 适合 Studio 版本和小团队授权。

### 8.5 RemoteTerminal 专业版

建议后续功能：

1. 自动重连。
2. Terminal Search。
3. 会话日志。
4. 分屏终端。
5. 命令片段。
6. 端口转发。
7. 跳板机。
8. 多文件传输队列。
9. 远程文件编辑。
10. 便携加密凭据 vault。

商业价值：

- 开发者工具用户通常付费意愿更稳定。
- 可以独立形成 DevOps Pro 版本。
- 与本地文件、SFTP、素材发布工作流结合后，有组合价值。

### 8.6 AppStorage 与清理助手

建议后续功能：

1. 清理建议，但初期只做建议不自动删除。
2. 应用缓存识别规则。
3. 风险等级和可恢复性提示。
4. 空间变化历史。
5. 一键导出空间报告。
6. 与 Duplicate Finder 合并为 Storage Suite。

商业价值：

- 面向普通 Windows 用户，理解成本低。
- 可作为 Free 版本获客入口。
- 高级报告和批量清理可进入 Pro。

### 8.7 平台与生态功能

建议中长期功能：

1. 插件系统：允许新增面板、任务、索引器、导出器。
2. 模型管理中心：模型下载、版本、许可、设备能力、重建策略。
3. 私有同步：只同步索引元数据或配置，不默认同步原文件。
4. CLI / 本地 API：让高级用户把索引、搜索、导出接入脚本。
5. 企业离线安装包：包含模型、FFmpeg、策略配置和审计文档。
6. 工作区概念：不同项目、客户、素材库独立索引。

## 9. 产品路线图建议

### Phase 1：商业 MVP（工程主链已完成，发布门禁未关闭）

目标：把当前项目包装成可试用、可演示、可反馈的个人 Pro 工具。首次引导、统一任务、来源健康、证据展示和恢复等自动工程项已经完成；当前重点转为真实用户验证、许可证、签名、政策和干净安装包。

重点：

- 首次启动向导。
- ImageSearch 稳定化。
- MediaSearch 真实样本验证。
- 统一任务中心。
- 索引健康面板。
- 授权能力开关。
- 崩溃日志导出。
- 核心官网/说明文档/演示素材。

- 主要面板打开不卡顿、无白屏。

### Phase 2：素材资产管理（核心能力已完成）

目标：从“搜索工具”升级为“素材资产库”。分类、标签、建议、聚类、备份和统一素材身份已经形成核心能力；后续重点是工作室真实流程、迁移稳定性和共享边界。

重点：

- Asset Library 独立面板。
- 分类、标签、相似组。
- 未分类素材处理队列。
- 参考图分类。
- 批量导出和报告。
- SQLite/本地索引迁移方案。

验收标准：

- 用户可以把一个素材目录整理成分类库。
- 可以通过图片、文本、标签、相似组多入口找回素材。
- 索引状态可解释、可修复、可迁移。

### Phase 3：视频知识库（语义与导出主链已完成，外部门禁待处理）

目标：把 MediaSearch 打造成高差异化付费功能。ASR、视频/音频语义、命中时间范围、播放器导航和片段/时间线导出主链已经接通；真实素材人审、模型再分发决定和大库长期运行仍是上线前门禁。

重点：

- ASR。
- OCR。
- 时间线结果。
- 片段导出。
- 视频内容标签。
- 多模态查询模板。
- 大视频库 benchmark。

验收标准：

- 用户可以用文字、图片或字幕定位视频片段。
- 搜索结果可跳转、导出、截图。
- 大目录扫描有明确耗时和失败统计。

### Phase 4：团队与企业离线版（未来阶段）

目标：进入小团队、工作室、隐私敏感客户。

重点：

- 私有模型包。
- 企业策略。
- 离线部署文档。
- 支持服务流程。

验收标准：

- 可以离线安装。
- 可以导入模型和 FFmpeg。
- 可以导出问题诊断包。
- 可以按团队或设备授权。

## 10. 商业化风险

| 风险 | 表现 | 建议 |
| --- | --- | --- |
| 功能范围过宽 | 用户不知道产品主卖点 | 对外先主打 ImageSearch / MediaSearch，不把所有面板同等展示 |
| 上手成本高 | 模型、FFmpeg、索引概念复杂 | 做首次启动向导和健康检查 |
| 大库性能不稳定 | 索引慢、搜索卡顿、内存高 | 建 benchmark、性能预算、索引 meta、ANN/SQLite 迁移 |
| 模型许可风险 | 商业构建中模型来源不清 | 建模型许可白名单和可选下载策略 |
| Windows 依赖较强 | AppStorage、部分路径能力偏 Windows | 先明确 Windows 优先，跨平台作为中长期方向 |
| UI 复杂度高 | 面板多、功能密集 | 做模式分层：基础模式、专业模式、任务中心 |
| 付费边界模糊 | 免费版过强或 Pro 不明确 | 以索引规模、批量能力、视频/AI 高级能力区分 |
| 支持成本高 | 本地环境差异、FFmpeg、GPU、模型问题 | 做诊断导出、环境检测、可降级 CPU 路径 |
| 开源与商业边界反复 | 外部贡献无法再许可、社区版价值不足或商业能力被意外开放 | 首个外部贡献前批准许可证、贡献机制、社区价值闭环和商业模块边界 |
| 基金会过早 | 增加治理、商标、财务和合规成本但没有多组织社区 | 先公开运行并培养独立维护者，只在中立治理能解锁采用与赞助时迁移 |

## 12. 建议的对外卖点文案

### 12.1 面向创作者

本地 AI 素材搜索工具。用图片、文字或视频画面找回散落在硬盘里的素材，不需要上传到云端。

### 12.2 面向视频用户

在本地视频库中搜索画面和字幕。选择一张图或输入关键词，快速定位视频中的对应时间点。

### 12.3 面向开发者

一个常驻桌面的开发者工作台，集成文件管理、远程终端、SFTP、重复文件查找和本地 AI 检索。

### 12.4 面向隐私用户

本地索引、本地检索、本地缓存。适合私有素材、客户文件、内部视频和离线工作环境。

## 13. 投资与商业判断

### 13.1 值得继续投入的理由

1. 当前工程已经不是概念验证，核心链路可运行、可构建、可测试。
2. ImageSearch 和 MediaSearch 都有明确痛点，演示价值强。
3. 本地优先在隐私、离线、大文件场景有天然优势。
4. 多面板工作台有扩展空间，可以承载插件、模型、任务中心和工作区。
5. 当前安全和测试基础较好，具备继续产品化的条件。

### 13.2 不应盲目投入的方向

1. 不应马上扩成全平台云服务。
2. 不应同时主推所有面板，容易稀释卖点。
3. 不应在未完成真实性能审计前承诺超大规模视频库。
4. 不应默认内置许可不清晰的模型。
5. 不应过早做团队协作云同步，先把本地单机价值打穿。

### 13.3 推荐商业切入点

第一商业切入点：ImageSearch + MediaSearch 的个人 Pro 版本。  
第二商业切入点：Asset Library 的 Studio 版本。  
第三商业切入点：RemoteTerminal 的 DevOps Pro 版本。  
第四商业切入点：Enterprise Offline 离线部署和支持服务。

## 14. 结论

Siftory（寻藏）当前已经具备从“桌面工具集合”升级为“本地 AI 工作台”的基础。它的商业价值核心不在于单个面板，而在于把本地文件、图片、视频、远程主机和 AI 检索连接成一个可持续使用的桌面工作流。

近期最重要的产品策略仍然是聚焦：对外优先包装本地图片/视频搜索与素材工作流，内部以统一搜索、Asset Library、任务/健康中心、播放器和专业导出形成稳定闭环。只要真实用户能够稳定完成“导入目录 -> 建索引 -> 找到目标素材 -> 打开或导出结果”，并愿意为官方发行或专业能力付费，项目就具备个人 Pro 和小团队 Studio 商业化基础。

下一阶段建议以可发布 MVP 和真实付费验证为目标，而不是继续单纯追加功能。开源可以提升本地数据产品的信任、适配和生态，但不能替代许可证清理、质量验收和商业需求验证；基金会也应由真实的多组织社区需求触发，而不是作为发布前的品牌包装。

## 15. 开源、商业售卖与基金会路径

2026-08-19 已形成[开源、商业化与基金会路径草案](../current/2026-08-19-open-source-commercialization-foundation-strategy.md)。当前建议是“先验证商业价值并完成公开准备，再开放有清晰权属的核心，最后按社区事实决定基金会”，而不是直接公开当前工作区或立即注册独立基金会。

建议的长期分层是：

1. 社区核心提供本地扫描、稳定素材身份、索引格式、基础图片/视频搜索、模型适配和插件接口，并保留一条可独立使用的真实价值闭环。
2. 官方产品通过签名安装、稳定更新、兼容矩阵、诊断、经过批准的模型/运行时分发和明确支持责任收费。
3. Pro/Studio/Enterprise 通过专业工作流、团队/NAS 协作、企业策略、离线部署、定制集成和 SLA 收费。
4. 模型权重、FFmpeg、CUDA/cuDNN、测试素材与第三方运行时继续分别遵守自己的许可证；项目开源许可证不自动覆盖它们。
5. 先用公开治理、维护者晋升、RFC、安全披露和商标政策建立社区；出现独立维护者、多组织采用和长期赞助后，再比较现有基金会托管方案。

该路径目前是草案。项目仍为 `private + UNLICENSED`，机器可读发布路线仍由 `legal/license-decisions.json` 和[商业发布准备专项](../current/2026-08-17-commercial-release-readiness.md)约束。任何正式改变都必须由真实权利主体批准，并同步许可证、贡献协议、EULA、构建 profile、NOTICE 和发布门禁。
