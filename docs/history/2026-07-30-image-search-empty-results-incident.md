# 2026-07-30 以图搜图空结果事件

## 摘要

2026-07-30 用户连续两次报告“以图搜图没有结果”。第一次修复了 Renderer 结果被旧路径筛选隐藏的问题，但真实界面复测仍失败。第二次从当前运行进程、真实 native 索引、DINO 推理和 Float16 缓存逐层复现，确认主要故障是交互搜索同步重建过期向量缓存并超时。

事件已由提交 `9e42bad` 和 `f9975f7` 修复，用户随后确认搜索恢复正常。

## 影响

- 影响入口：Image Search 的图片查询，尤其是简单模式和高级模式的 Standard/Precise 搜索。
- 典型表现：搜索完成后结果区为空；普通视觉相似图片没有足够接近的 perceptual hash 候选。
- 未受影响：native 索引加载、hash 精确/近重复检索、DINO 单图推理、已有 Float16 缓存文件本身。
- 数据安全：事件与修复均未重建、迁移或删除用户的图片索引和向量数据。

## 根因

### 根因一：Renderer 残留筛选状态

`ImageSearchPanel` 发起新图片查询时没有清空上一次的路径筛选和另一搜索模式的结果。`ImageSearchResultGrid` 又使用原始结果数而不是过滤后结果数判断空态，导致后台已有命中时仍可能呈现完全空白的网格。

修复：

- 新查询开始时清空路径筛选、hash 结果和 layered 结果。
- 结果计数统一使用当前展示源。
- 按过滤后的结果数显示空态，并明确提示“当前路径筛选排除了全部结果”。

### 根因二：交互查询同步刷新 7.25 GiB 向量源

当前 DINO Float16 缓存包含 295,339 条向量，生成于 2026-07-27。后续 embedding 构建更新了 `dinov2_vitb14__global.jsonl`，使缓存的新鲜度校验失败。

Standard/Precise 查询随后调用 `ensureEmbeddingF16Cache`，在 30 秒交互查询超时内尝试从约 7.25 GiB JSONL 重建约 432 MiB Float16 缓存。重建未完成即被取消，搜索降级为 hash-only；对于没有近重复 hash 的普通查询图，最终结果为 0。

修复：

- 交互搜索优先读取最后一份结构完整的 Float16 缓存，即使源 JSONL 后续增长。
- 完整性仍校验版本、模型、embedding 类型、维度、记录数、向量文件精确字节数和路径索引存在性。
- 维护/构建流程继续使用严格源文件新鲜度校验并负责刷新缓存，交互查询不再承担数 GiB 重建任务。

## 诊断证据

- 当前运行应用确认来自主目录和最新提交，不是未重启或运行旧安装包。
- native manifest：184,301 条记录、1 个活动 segment。
- native 真实图片查询：返回非空结果，首条相似度为 1。
- 最近保存的查询图片可生成 768 维 DINO 向量。
- 直接搜索完整 Float16 缓存返回 200 条候选。
- 295,339 条缓存路径中，170,812 条仍属于当前 native hash 索引。
- 缓存文件约 432 MiB；DINO JSONL 约 7.25 GiB，且修改时间晚于缓存。
- 修复合并后 Vite 将 Electron 主进程从 PID 17884 重启为 PID 3484；用户在新进程中复测正常。

## 防回归规则

1. 查询 UI 的“原始结果”“分层结果”“路径筛选”必须在新请求开始时形成单一、明确的状态切换。
2. 交互请求不得同步构建或迁移数 GiB 派生数据；必须使用最后可用快照、后台刷新或明确的准备流程。
3. 缓存“过期”与缓存“损坏”必须区分：过期快照可以降级读取，损坏快照必须拒绝。
4. 以图搜图回归至少同时覆盖：
   - native hash 命中；
   - 非索引查询图的 DINO 向量检索；
   - 源 JSONL 晚于缓存时的交互检索；
   - 路径筛选排除全部结果时的可见提示。
5. 故障判断必须以当前运行进程和真实用户数据只读探针为准，不能只依赖孤立单元测试。
