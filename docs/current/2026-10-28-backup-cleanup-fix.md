# Alpha 11 备份清理与诊断修复

> 状态：当前
> 更新日期：2026-10-28
> 范围：自动维护 GC 恢复备份清理；版本保持 1.0.1-alpha.11

## 问题与修复

Alpha 11 的 Windows CI 在核心行为测试中过期备份清理断言失败（191 项，190 通过、1 失败）。本地普通路径下原有 11 项维护测试通过，但使用指向真实目录的路径别名，可以确定性复现清理量为零：旧实现直接比较输入路径与 realpath，把用户配置根目录的合法祖先别名也拒绝掉。该复现证明路径处理缺陷；Windows CI 的最终结果需单独核验，不用本地通过替代。

现在先解析可信用户配置根目录，再检查其内部 vector-db 与 embeddings 目录。两层存储目录均拒绝符号链接/目录联接，继续核验真实路径、目录和文件身份、元数据配对、保留期限、取消与删除前一致性。原始向量分片和近期恢复备份仍不可删除。没有通过放宽保留期限、忽略断言或跳过 Windows 测试来处理失败。

清理接口保持返回实际回收字节数，增加可选汇总接收器，默认输出一次结构化摘要。分类记录不安全目录/文件、无效元数据、未到期、文件变化、配对缺失、取消和 I/O 错误；I/O 仅记录白名单错误码及计数，不记录文件路径、名称、元数据内容或异常消息。

同时修复计数边界：备份已删除而元数据删除失败时，仍报告已回收的备份字节；残留元数据保持原位，后续不会误删活动分片。

## 回归与验证边界

`tests/automatic-maintenance.test.cjs` 现有默认测试入口继续可达，新增祖先路径别名、内部两层目录链接拒绝、权限失败/无效 JSON 的诊断、部分删除计数和取消保护。新增路径别名用例在旧实现上失败，修复后维护测试 16 项通过。修改模块定向 TypeScript、修改文件 ESLint/Prettier、导入分层和构建图另行检查。

真实用户库、覆盖安装和共享盘故障演练未在本轮执行。GitHub Windows CI 结果以对应提交的 Actions 记录为准。大收藏夹数据库分页、大库压测、发行签名和架构拆分仍属后续工作。

Windows CI 后续确认核心行为 196 项通过。继续运行到桌面浏览器阶段时，暴露出 Alpha 11 的另一处测试定位问题：通用 `data-ready` 同时匹配应用根节点与准备状态卡片。工作台与现代桌面的页面就绪等待改为同时匹配 `app-root` 和 `data-ready`；不使用 first() 或跳过检查来掩盖选择器歧义。权限故障注入按测试目录内唯一文件名匹配，并断言错误实际触发，避免依赖 Windows 路径别名文本。

浏览器回归还改为等待原有卡片尺寸条件，而非缩放后固定等待 150ms；快捷键输入框提供非可见的录入就绪标记，测试等待主进程确认后才发按键。录入保护与原尺寸断言保留。本地四条浏览器回归随后全部通过，现代桌面产生 84 张检查截图，页面错误为零；Windows 整体结果继续以 Actions 为准。
