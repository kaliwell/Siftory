# Alpha35：JPEG 文件头检查及失败明细

2026-11-16 的 Alpha34 复测日志显示，本轮剩余十项失败：六项像素超限，四项在同一次 DINO 子进程异常退出后失败，退出码为 Windows 0xC0000409。批次内所有任务都会受子进程退出影响，不能由此断言四个文件全部损坏，也不能证明是 GPU 或某个解码器的故障。

## 修改

- JPEG 文件头检查改为按段定位，跳过 APP/COM 元数据负载后寻找 SOF 尺寸和编码。累计读取不超过 64 KiB、最多 1024 个段，不是把前 64 KiB 当成完整头；预算耗尽仍为不确定结果。文件大小、修改时间及路径对应文件身份变化时不归为确认跳过。
- DINO、CLIP 的正常和预取解码入口在调用原生解码器前检查 JPEG 编码。独立确认的算术编码、非 8 位或当前不支持的无损 JPEG 不再进入解码器，进入既有失败后复核、跳过计数及日志流程。检查不确定的文件仍交由原有解码器处理。
- 模型像素预算保持原值，不关闭保护。失败后读取到的真实尺寸超过当前模型限额时才归为像素超限跳过。
- 统一错误报告新增保留下来的逐项向量失败，除最终总数外也可查看原始错误及模型。真实子进程、GPU、模型和持久化错误继续保留，不因源文件名称或目录而隐藏。

这些修改覆盖本次日志揭示的检查缺口。六个大图为何未能在 Alpha34 头检查中取得尺寸仍需原始文件验证；大型元数据是可复现的缺口，不是已证实的全部根因。四个测试样本是否全部被提前识别也需本地复测。没有扩大输入解码能力，没有自动排除整个 Cargo 目录。

## 验证与边界

本地输入复核/服务/管线/Worker 生命周期/日志套件 45 项、输入验证及调度性能逻辑 9 项、架构 22 项通过；修改文件 ESLint、生产构建通过。新增测试用合成 JPEG 验证跨过多个大型 APP 段、实际读取预算、恶意填充头的退出、特殊编码不会调用解码操作、正常 JPEG 保持原解码路径，运行时错误不会误归为跳过。

云端没有用户的原始文件，也没有真实 GPU 建库验收。Windows 安装包启动与回归结果在构建完成后单列；安装后请再准备同一素材库，完成后导出扫描与预览错误日志。原生扫描的历史跳过计数及历史 embedding_failures.jsonl 不清空。
