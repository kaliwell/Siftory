## 数据权威与迁移边界

| 数据                                  | 权威来源                   | 其他存储的角色                                 |
| ------------------------------------- | -------------------------- | ---------------------------------------------- |
| 原始图片、视频、PSD/AI 等文件         | 用户选定来源中的原文件     | 索引和向量不是原文件备份                       |
| 已收录图片记录及删除覆盖              | Native 索引和 overlay      | 不能用物理 manifest 总行数代替有效记录数       |
| 统一来源、文件条目及稳定 FileEntry ID | Discovery Catalog SQLite   | 旧索引兼容投影仅接纳后台已证明收录的路径       |
| 收藏、标签、分类等用户元数据          | 素材库的现有权威存储       | 同步/迁移须保留恢复标记和补偿流程              |
| 视频、抽帧及缺失状态                  | 对应视频清单和帧索引       | 视频帧数不能当作原视频数或原图片数             |
| 已生成模型向量                        | 当前模型分片或已提交权威代 | F16/ANN 是可重建派生数据，不能反向批准未知素材 |
| 统计快照                              | 只读分析目录               | 没有快照表示未统计，不表示没有索引             |

本轮不合并或删除现有数据库，不改变已冻结的数据格式。旧索引向 Catalog 的兼容投影继续存在；它保护当前用户升级体验，未来整体退出应作为单独的可恢复迁移任务，不能通过删除兼容代码完成。统计必须标明原始素材、模型向量、视频帧、候选集合或分析快照的范围。

## 性能与验证说明

`npm run benchmark:core-search` 只构造临时 SQLite 数据和虚拟文件记录，不读取用户图库、运行目录或模型。31 次采样覆盖文件名检索、6,000 张图片之后的视频匹配和修改日期范围。输出位于忽略提交的 `artifacts/benchmark/core-search/latest.json`。这是目录与过滤路径的微基准，不代表真实素材扫描、GPU 推理、NAS 或安装包性能；跨机器比较须匹配环境与夹具版本。

更大规模的实际素材、内存和固定硬件测试仍使用现有 `benchmark:*` / `automation:*` 流程及其隔离要求。不能用本轮微基准取代完整真实模型验收。
