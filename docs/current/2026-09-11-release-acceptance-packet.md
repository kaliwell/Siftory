## 1. 统一记录与执行约定

每次运行先固定：任务 ID、执行人、日期、提交 SHA/未提交差异摘要、应用版本、配置、硬件/系统版本、数据集指纹、模型版本与实际 provider、profile、语言、步骤和接受阈值。每个案例记录 `通过/失败/未验证`、观察值、日志与截图的相对路径、输入前后摘要及问题编号。

模板字段：`caseId, taskId, executor, startedAt, sourceSha, dirtyDiffSha256, artifactSha256, osBuild, hardwareId, profile, locale, datasetFingerprint, modelRevision, actualProvider, expected, observed, result, evidencePaths, issueId`。任何字段缺失需要解释，不用空值代替“通过”。公开报告脱敏，原路径、凭据和媒体内容只在受控私有记录中保存。

首次执行前核对预检和脚本参数；故障测试仅针对指定的隔离副本。前置条件不满足记录未执行，不把夹具或历史报告复制成当前实机结果。

快速入口：[故障矩阵](#2-val-906-真实来源与窗口故障矩阵)、[搜索质量](#3-val-907-搜索质量协议与标注模板)、[性能](#4-val-908-正式性能剩余项与运行计划)、[安装](#5-val-909-干净-windows-安装验收)、[发布材料](#6-val-910-发布决策材料索引)。

## 2. VAL-906：真实来源与窗口故障矩阵

每类来源至少一个受控测试位置；本地、移动盘、挂载网络、SFTP 使用同一批可比的小型素材副本。准备用户可核对的文件摘要、目录清单及人工收藏/标签；设置好备份与恢复位置后再注入故障。

| ID | 条件与步骤 | 必须观察到的结果 | 证据 |
| --- | --- | --- | --- |
| SRC-01 | 网络来源扫描中断开测试连接，再重连并检查来源 | 离线提示真实；旧目录保留；重连可继续；无重复资产或误删 | 扫描前后条目数、任务状态与连接日志 |
| SRC-02 | SFTP 按需取回视频时中断连接，重连后重试 | 未完成文件不作为成功结果；重试得到完整文件；播放器打开正确素材 | 目标摘要、临时文件状态、播放命中 |
| SRC-03 | 对测试账户撤销读取权限后扫描，再恢复权限 | 明确权限错误而非空库；恢复可扫描；凭据不出现在日志 | 权限配置摘要、脱敏错误及恢复结果 |
| SRC-04 | 移动盘扫描/建库时安全模拟掉盘，然后重新连接 | 不把来源暂时不可达当作永久删除；任务可恢复且条目身份稳定 | 原始文件摘要、来源 ID、重建/恢复记录 |
| SRC-05 | 在独立限额测试卷制造索引写入空间不足，释放空间后重试 | 原子提交、错误可见、已提交数据可读；重试后无半文件和孤儿任务 | 测试卷、journal 状态、前后可查询条目 |
| SRC-06 | 对隔离应用实例在扫描、向量提交、备份恢复阶段分别强退并重启 | 原始素材不变；已提交状态可读；未完成任务明确可恢复或失败 | 各阶段故障点、事务状态和重启后验证 |
| SRC-07 | 对测试副本执行来源派生数据清理后只读检查所有派生层 | 原文件与人工元数据保留；指定 Native/DINO/CLIP/主体/缩略图/视频派生层无残留 | 各层计数和前后摘要；承接 SRC-008 |
| WIN-01 | 双窗口、拖动中、缩放中分别隐藏/显示，再点击桌面与面板 | 隐藏不拦截点击；恢复无空白闪帧；交互不粘住 | 录屏与 visibility generation 日志 |
| WIN-02 | 注册冲突快捷键并触发设置诊断 | 冲突逐项可见；正常快捷键仍可用；不显示全部成功 | 设置状态与实际按键结果 |
| WIN-03 | 扫描、远程连接、窗口显示期间分别休眠/唤醒 | 状态可解释；来源重连可恢复；无持续挂起或透明窗口截获 | 唤醒前后状态、连接与交互记录 |

共同硬失败：原文件损坏、人工元数据丢失、错误来源串写、未授权路径操作、秘密出现在诊断、失败被报告成成功。每一硬失败修复后重做同案例及相邻恢复路径。设备来源、睡眠和真实点击不能用 Node 单测替代。

## 3. VAL-907：搜索质量协议与标注模板

### 3.1 冻结数据与真值

首轮受控集至少 100 条有相关结果的查询，按文字找图、以图找图、视频画面、对白、混合查询各 20 条分层；另加至少 20 条无相关结果查询。每组覆盖普通、困难、跨来源和相似但不相关样本。每类视频 profile 的覆盖单独记录，不能用少量统一查询替代既有 8×10 描述验收。

在有界固定语料内完整枚举相关结果，给每个查询建立相关资产集合与视频时间区间。若只能审核召回候选池，报告必须标为候选池内召回，正式 Recall@K 仍未就绪。示例图自身、训练/原型样本必须按既有规则排除；查询集不能用最终测试结果反向调整。

人工标签模板：`queryId, queryType, queryTextOrImageId, sourceScope, corpusFingerprint, relevantAssetId, relevantStartMs, relevantEndMs, relevance(0/1/2), evidenceCorrect, reviewer, reviewedAt, disagreementResolution`。文字和图片仅保存在受控数据目录；发布摘要使用匿名 ID。

### 3.2 预先登记的工程验收目标

以下是本轮新增统一搜索验收的工程目标，不是当前实测值或对外性能承诺；执行者需在跑数前将其与语料指纹一起冻结。既有 Neko 门禁必须另外通过；不能用本表放宽原门槛。

| 指标 | 定义 | 首轮工程接受条件 |
| --- | --- | --- |
| Recall@10 / Recall@50 | 每条有相关结果查询的已召回相关数 / 全部相关数，按查询宏平均 | 各通道分别 >= 0.80 / 0.90；同时报告样本数和置信区间 |
| Hit@10 | Top10 至少一个相关结果的查询比例 | 每通道 >= 0.90，不以易样本平均值掩盖失败通道 |
| 排序回退 | 同一语料、同一真值的 nDCG@10 与冻结对照比较 | 下降不超过 0.02；同时列出逐查询差异 |
| 命中依据正确性 | 人工核对已展示依据与原素材对应情况 | >= 0.90；错误文件关联和伪造不存在的依据为硬失败 |
| 视频时间误差 | 预测点到最近相关真值区间的距离，落在区间内为 0 | P50 <= 2 秒、P95 <= 5 秒；报告所有适用查询，不删除困难样本 |
| 无相关结果 | 人工核对无结果查询的提示、结果置信描述 | 不把低置信候选标成确定命中；另报告误报比例，不假定系统一定输出空列表 |
| 数据源一致性 | 对同一授权素材在本地与远端建立稳定身份后核对 | 打开、定位和按需取回的文件摘要与命中身份一致 |

Neko 复用 `annotation:neko:acceptance` 与 `benchmark:neko-search:accuracy` 的现有协议和冻结基线。当前活动集数量不同，需要固定同集重建对照；不得直接 `--write-baseline` 覆盖旧证据。五类标注、人工占比、原型排除与聚类指标沿用[既有准确率门禁](../benchmark/2026-07-18-neko-search-accuracy-gate.md)。

输出：匿名查询级 CSV、各通道指标 JSON、总体 Markdown、数据/模型/排序指纹和错误案例列表。未达标时修复或明确缩小首版能力承诺，重新冻结后的独立验收不能冒充原轮通过。

## 4. VAL-908：正式性能剩余项与运行计划

复用[2026-08-26 接受基线](../benchmark/2026-08-26-fixed-hardware-first-build-baseline.md)及[内存专项](2026-08-28-runtime-memory-optimization-todo.md)。本计划不更改 accepted 指针、配置或控制线。

| 待闭环项 | 场景与顺序 | 证据/接受条件 |
| --- | --- | --- |
| RMO-005 | 当前候选代码、固定硬件和数据三轮首建 | 隔离 userData、同一 identity、实际 provider、完整时间线 |
| RMO-032 / 036 | DINO 预处理候选与 jobs/batch/overlap 配对矩阵 | 1000 图 AB/BA/AB；张量/向量/索引 parity；候选默认关闭至通过；Ready P95 不回退 5% |
| RMO-045 / 047 | GPU 进程、VRAM 与 1/2/8 lanes 的 10k 混合大图 | 画面一致、无隐式 CPU fallback；内存/吞吐满足专项阈值 |
| RMO-050 | 1000 固定查询、600 次面板生命周期、2 小时混合负载三轮 | 结果摘要稳定、采样完整、资源释放可证；已有短场景结果不替代长负载 |
| RMO-052 / 054 / 055 | 读写边界、最终工程回归、新控制线接受 | 输入前后摘要一致；最终源码与三轮证据绑定；指针更新依专项审核 |
| 周期诊断 | 每周 8 小时负载 | 独立安排维护窗口；输出长期趋势，不与 2 小时正式结果混算 |

同配置绝对控制线：Ready P95 <= 297190.28 ms，主进程 RSS P95 <= 790.63 MiB，子进程聚合 RSS P95 <= 3815.63 MiB，保守合计 RSS P95 <= 4544.51 MiB，系统最低空闲 >= 1012.92 MiB，三轮 Ready 极差 <= 15%。这些来自既有固定基线，不能跨机器直接作为对外承诺；配对候选还须满足其专项更严格阈值。

预检：运行 `npm.cmd run benchmark:memory:preflight`，核对 RAM/GPU 静默、AC、电源、进程与 accepted identity。预检失败只登记缺失条件，不关闭用户程序、不添加杀毒排除、不启动高负载；条件恢复后整轮重做。正式执行前固定 runs、duration 和输出目录，保存每轮原始数据，不移除异常值。

## 5. VAL-909：干净 Windows 安装验收

四个必测组合：Online/zh-CN、Online/en、Offline/zh-CN、Offline/en。每个组合从干净虚拟机快照或独立测试设备开始，无开发工具链、开发目录、缓存和预置外部模型。记录 OS build、架构、GPU/驱动、RAM 和安装包 SHA-256；具体支持的系统版本以最终发布范围为准。

| ID | 操作 | 接受结果 |
| --- | --- | --- |
| INS-01 | 检查安装包签名、安装位置、普通用户安装与启动 | Valid 签名和时间戳；无需开发工具；身份与发布说明一致 |
| INS-02 | 新配置跳过首次引导，再重新进入添加本地副本 | 引导可恢复；不扫描未选择位置；配置持久 |
| INS-03 | Online 缺模型：检查状态，用户同意后准备，途中取消再恢复 | 无自动越权下载；状态、校验、取消和修复真实；不要求手工复制开发缓存 |
| INS-04 | Offline 断网准备随包支持的基础模型与工具 | 承诺随包组件可用；可选外置能力明确不可用及后续准备条件 |
| INS-05 | 导入固定小型素材、建库、文字与图片查询、视频定位 | 至少得到预先标注的正确结果，打开和时间点正确；模型缺失分支仍能元数据搜索 |
| INS-06 | 结果导出、备份、错误密码导入、正确恢复 | 字段/文件正确；错误密码拒绝；正确恢复保留人工元数据 |
| INS-07 | 在旧版配置副本上升级，并模拟迁移失败与回滚 | 原文件、设置、集合保留；失败不使旧数据不可恢复 |
| INS-08 | 卸载、重装和按用户选择恢复数据 | 与既有卸载保留策略一致；原始媒体不删除；保留数据可重用 |
| INS-09 | 导出健康报告，切换中英文后再次检查 | 无路径/凭据泄露；错误和降级文案一致，支持入口可访问 |

生命周期每格记录实际结果，安装恢复夹具只作前置。剪辑导出还需在计划承诺的目标应用中单独记录导入版本与结果。任一修复导致包字节变化，重新绑定哈希并执行受影响组合。
