# 首次图片搜索进度与缓存诊断

> 状态：部分实施

对应 [Issue #1](https://github.com/kaliwell/Siftory/issues/1)，基于 Alpha32 发布分支。此修改修复进度与空状态，并补充定位首次搜索耗时所需的证据；未将覆盖安装后首次搜索缓慢宣称为已解决。

## 行为变更

- 图片搜索进度显式携带工作阶段、计数单位和阶段吞吐；缓存构建显示 MiB/s，压实与逐条检索显示条/s。阶段切换后重置计时和速度，ETA 仅由该阶段已完成量与总量计算。没有总量的加载阶段不显示虚假百分比或 ETA。
- 搜索期间空结果区显示“正在搜索图片”，结束后才判断无结果。
- 模型子进程报告实际模型加载与推理阶段，并回传模型加载、图片解码、推理和后处理耗时。记录模型子进程是否复用。
- 记录 F16 缓存选择、格式与完整性拒绝原因，以及 ANN 的构建方式、重建原因、索引读取字节和实际检索耗时；逐条 JSONL 回退也报告阶段与字节进度。
- 数据目录及缓存位置使用现有诊断身份密钥生成的标识，方便对照升级前后的位置是否变化。沿用现有诊断脱敏、留存、导出与清除机制，新增记录不包含图片或向量内容。
- 继续使用既有持久化缓存选择和完整性校验规则；没有变更安装器、缓存格式或使校验失效。

## 诊断解释

现有“搜索诊断”导出包含以下新增事件：

- `search-storage`：脱敏的数据位置与缓存位置标识。
- `query-runtime`、`query-inference-timings`：子进程复用、模型加载与查询图处理耗时。
- `search-stage-start/end`：图片搜索阶段时间线。
- `vector-stage-start/end`：向量检索内部阶段时间线，末阶段记录完成或异常结果。
- `f16-cache-probe/selection/ready`：缓存类型、命中、拒绝原因和记录规模。
- `ann-search-summary`：持久化侧车或内存复用、重建原因、读取量及耗时。
- `vector-search-fallback`：ANN 不可用、结果不足或禁用后的回退原因。

搜索与向量阶段时间线属于嵌套视图，不能相加。ANN 的 `searchMs` 已包含 `loadMs`，`retrievalMs` 排除了加载；不要再次把两者重复相加。

## 验证

- TypeScript 前后端类型检查、修改源文件 ESLint、格式检查及前端/Electron/Worker 生产构建通过。
- 缓存、重排、向量有效性、进度计量和诊断存储：30 项通过。
- 国际化、缓存内容证明、分块完整性、进度及向量有效性：27 项通过（部分与上一组重叠）。
- ANN、ANN 内容证明、子进程二进制协议及基准协议：21 项通过。
- 真实 React 浏览器回归通过，使用模拟 IPC 验证 MiB/s 与条/s 切换、搜索中空状态、完成后无结果、取消及旧响应隔离。此项不是 Windows 原生客户端或真实模型推理验收。
- 新进程读取兼容的合成 F16 缓存，确认命中且向量文件未被重写；损坏与旧格式分别报告校验失败和格式不兼容。

### 本机现有缓存测量

读取本机现有 220,446 条 DINO 向量缓存，未导出路径、图片或向量内容。以下是一次运行结果，不是覆盖安装基准：

| 测量           |    首次 | 同进程第二次 | 重启 ANN Worker |
| -------------- | ------: | -----------: | --------------: |
| F16 缓存校验   |  997 ms |         1 ms |            未测 |
| ANN 调用总耗时 | 2733 ms |       702 ms |         3060 ms |
| ANN 索引加载   | 1949 ms |         0 ms |         2264 ms |
| ANN 是否构建   |      否 |           否 |              否 |

ANN 使用合成单位查询向量，未运行查询图片推理、哈希检索或完整工作台搜索。首次及重启 Worker 均复用已有侧车，只读取约 34.1 MiB 路径索引；同进程第二次复用内存。测量前后相关持久化缓存文件修改时间均保持不变。
