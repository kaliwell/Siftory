## 关键决策

1. **车道隔离证明 D1 不被阻塞（8.2 约束 1/2）**：GPU 重任务（D5/D6）与本地 IO 任务（D1-D4）走独立队列与独立并发预算（local 默认 4、gpu 默认 1），没有任何共享锁或共享执行循环；测试在 GPU 车道占满（1 运行 + 1 排队）时验证 D1 在 2s 内完成。
2. **优先级语义（8.2）**：默认映射 D1/D2→P1、D3/D4→P2、D5/D6→P3；显式优先级优先于阶段秩，同级按阶段秩（discovery 最前）再按入队序。`setVisiblePaths` 实现 P0：可见路径命中的排队任务提到队首（可见区域优先生成预览与 embedding，Phase 3 任务 4）。
3. **AI 不可用路径（9.2）**：语义车道以 `vectorHealth` 门控——`model-missing`（无召回提供方/模型缺失）、`vector-corrupt`（内容证明失败）、`index-stale`（未建库）均映射为明确 lane 状态 + 中文可操作提示；召回抛错→`task-failed`。每条 metadata-only 结果继承该 `degradedReason`，`aiEnhancement` 三态（ready/pending/unavailable）支持增量增强：同一查询在索引完成后合并语义分数并重排（测试覆盖前后两次查询）。
4. **路径键修复不碰权威数据**：向量/缓存是可重建派生物；修复只重写路径键并重钉派生证明（vectors 字节不动，行序不变）。权威代修复前先验证全部钉住证明，损坏即 `refused-corrupt` 且文件保持原样（不会在损坏字节上"修复"）。import 锚点（size/mtime/tailSha256）随被重写的 cache 文件重钉，`extendEmbeddingF16Cache` 的增量合并路径保持可用。
5. **语义召回真实接线**：主进程复用 `searchSemanticImages` 及其 `semanticVectorSearchWorker`，P0 查询经统一 GPU 车道执行；只有本地 CLIP 文本模型和已验证的 CLIP/global generation 同时存在才放行。命中路径必须回查 Discovery Catalog；未纳入来源目录的孤儿向量不会以空 `fileEntryId/source` 暴露。
6. **查询不修改身份权威**：统一结果只通过 `findByPath` 读取既有 Phase 2 AssetId，不调用 `resolveForPath` 自动创建映射；扫描或显式身份流程仍负责写入。
7. **移动修复部分完成可见**：IPC 先完成稳定身份/素材记录重指向，再修复 Catalog、Native manifest 和向量路径键。派生索引损坏时返回 `ok=false, repaired=true`，明确表示权威记录已移动但派生修复被 fail-closed 拒绝。
8. **图像查询显式适用性**：统一请求新增可选 `referenceImagePath`/`subject`。纯文本只运行 lexical + semantic；有参考图时主体召回复用 `searchBySubject`，重复召回只读资源库中已有 `duplicate_exact`/`duplicate_near` 组。未提供必需输入的 lane 返回 `not-applicable`，不再误报为模型缺失；所有命中仍经 Catalog 回填和来源过滤。
9. **只迁移完整生命周期任务**：可见缩略图的单图、文件夹封面和 renderer 有界批次分别作为一个 preview/P0 任务提交，批次内部沿用原有解码并发，避免最多 200 个 P0 子任务淹没 local 队列；显式 hash 作为 hash/P0。D6 将 `buildVideoFrameIndex` 的完整 FFmpeg/清单落盘 Promise 放入 GPU 车道，外部仍立即获得 taskId；排队取消后在启动 FFmpeg 前按 taskId/state 退出。D5 新增 `queued` 进度和 reservation：IPC 立即返回，调度任务在真正开始时启动 embedding 子进程，并监听 `done/error` 终态后才释放 GPU 车道；排队停止会取消 scheduler task，旧任务延迟拒绝用 reservation id 隔离，不能污染后续建库。
10. **保留 Native 单次读取复用**：legacy Image Search 在同一 C++ 解码中提取尺寸、双感知 hash，并把编码字节直接交给缩略图 sidecar。为避免按 D3/D4 强拆后重复读取大文件，生产 `startScan` 以 hash/P1 复合任务进入 local 车道；新增 `queued` 预约，排队时可取消，运行后一直持有车道到 Native 扫描、工程预览和 manifest 自动保存完成。终态监听会跨过 Native 先广播 `idle`、随后启动 autosave 的同事件循环窗口。
