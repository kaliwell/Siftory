> 原则：不删除原始图片或视频；无法证明“已删除”的记录一律保留

## 1. 问题结论

修改前，图片更新扫描只处理新增和变化文件，不会清除已经从磁盘删除的路径；视频重新扫描可以标记缺失，但没有充分区分“文件删除”“盘符离线”“扫描取消”和“目录读取失败”。这会造成图片搜索返回失效路径，或视频来源暂时离线时出现误标记风险。

## 3. 固定行为

1. 用户先选择盘符或文件夹，再执行只读检查。
2. 预览显示检查的图片/视频数量、已删除数量和无法访问但被保留的数量。
3. 确认时会再次检查；预览后恢复的文件不会从索引移除。
4. 图片记录通过 Native 精确批量删除从搜索范围移除；缩略图只按实际缓存清单反向匹配后有界删除，素材库同步启动后等待任务终态。DINO/CLIP 任务记录同步移除，权威向量 JSONL 追加 latest-wins 无效墓碑而不重写 4–7 GB 大分片。
5. 视频记录保留为 `missing` 墓碑，不参与搜索或建库。视频帧、转写和语义数据暂时保留，避免单个文件同步导致共享向量分片整体重建；可继续使用“按来源删除派生数据”做整段物理回收。
6. 盘符离线、目录无法读取、扫描取消或触发扫描数量上限时，不提交缺失记录。
7. 所有操作的 `originalFilesAffected` 固定为 `0`。
8. 同一预览令牌最多执行一次实际索引变更；重复确认返回缓存结果。执行失败后需重新检查，不能继续消费旧预览。
