## 已实施

### 原生记录写回

- 建立不落盘的路径键和记录位置缓存，已有内存记录直接定位。首次缓存建立只做一次；扫描、批量删除、压缩、加载和清空等改变记录布局的操作会使缓存失效。
- 更新和删除比较缓存键，避免每次重新规范化全部 Windows 路径。仍保留物理记录顺序、最新版本顺序和原有搜索同分行为。
- 变化记录仍有保持顺序的线性压缩，**没有宣称所有更新都成为 O(1)**；消除的是反复路径规范化和重复全表查找的高开销。
- 工程扫描使用 `upsertIndexRecordAsync`，复用既有异步工作注册、写入者准入和退出清理。同步 API 保留兼容。
- 新增仅取消本环境当前记录写回的入口；停止扫描不需要取消其他环境的搜索或维护。提交前检查取消，已提交记录保留合法结果。

### PDF 与任务调度

- PDF.js / Canvas 渲染转入受管理的独立子进程；一次只执行一个 PDF 任务。正常完成后复用同一进程，闲置 15 秒退出。
- 自动工程扫描先处理快速预览，再处理 PDF / PDF-compatible AI。不会仅因枚举顺序先遇到一个 PDF 就拖住所有 PSD。
- 自动扫描中的单文件 PDF 预算为 15 秒，并采样整个 PDF 子进程 RSS，软预算为 512 MiB；超时、超预算、取消或崩溃后，等待 owned process 退出才允许替代进程开始。
- RSS 每 100 ms 采样，可能过冲；不是操作系统硬内存上限。输出画布、单图像素和源文件原有安全限制继续生效。
- 非批量调用保留原来的 120 秒预算；显式选择源文件搜索/更新会绕过失败缓存重试。不是把全部 PDF 调用永久限制成 15 秒。
- PDF 资源失败记录稳定错误码及 30 分钟自动重试退避。源文件变更、显式重试或“全部更新”可再次尝试。
- 暂时失败保留上一次成功预览文件，条目仍标记失败，不把旧预览当作最新搜索结果。失败计数和中文状态警告会提示重试。
- 退出清理覆盖当前任务、排队任务和闲置进程。预览质量、最长边、JPEG 参数和搜索算法保持原值。

## 实测结果

### 真实工程预览阶段

此场景只计 386 个 PSD 和 1 个 PDF 的工程预览/写回阶段，**不包含前面的 919 张普通图片原生扫描**。

使用同一真实目录、已有 PSD 预览缓存及 20,000 条合成内存记录。优化前记录一轮；优化后重复三轮自动 `updateAll`，每轮都重新尝试 PDF，未利用 PDF 失败缓存制造加速。

| 指标                   |               优化前 |                                  优化后 |
| ---------------------- | -------------------: | --------------------------------------: |
| 387 个工程文件处理结束 |       128.29 s，单轮 |                     16.58 s，三轮中位数 |
| 首个 PSD 可用          |  先等待 PDF 约 120 s |                             0.05–0.26 s |
| 成功生成/写回的 PSD    |                  232 |                                每轮 232 |
| 无可用预览的 PSD       |                  154 |                                每轮 154 |
| 问题 PDF               |   失败，通用解码错误 |        失败，明确 `PDF_PREVIEW_TIMEOUT` |
| PDF 相关进程工作集     | 宿主采样约 1,323 MiB | 宿主 + PDF 子进程采样估算最高约 600 MiB |

约 128 秒到约 16.6 秒的变化，主要来自快速文件优先和缩短自动失败尝试的预算，**不是将该 PDF 成功渲染得更快，也不是整个目录扫描只需 16.6 秒**。进程隔离本身不减少 PDF 的累计解码字节数；本次内存收益还依赖时间及资源预算。

内存比较不包含两侧的 GPU / Network / Renderer 进程，基线和新版本采样方式不同，因此作为容量变化观察，不作为精确整应用峰值降幅。后台程序和 OS 缓存没有完全控制。

三轮新实现的诊断 Renderer 最慢 IPC 往返分别约 95、6.9、17.2 ms；主线程定时间隔最差约 106 ms。没有复现持续秒级阻塞，但也不宣称已消除所有长帧。这是最小 Electron IPC 页面，不等于完整 Windows 拖动验收。

### 大索引写回：三轮交替 A/B

每轮使用独立进程，交替执行基线二进制和优化二进制；119,000 条内存记录，同样的 24 个真实 PSD 预览路径、相同顺序及填充路径长度。以下均包含首次建立定位缓存的成本，取三轮中位数。

| 24 次写回        |       优化前 |    优化后 |             变化 |
| ---------------- | -----------: | --------: | ---------------: |
| 相同记录重复写入 |  5,450.63 ms | 207.99 ms | 耗时约减少 96.2% |
| 修改后写回       | 13,373.72 ms |  64.96 ms | 耗时约减少 99.5% |

另对完整 232 个预览复测：重复写回从诊断时的 66.34 s 到 0.241 s；修改写回从 126.38 s 到 0.820 s。这一组是单轮比较，不混作三轮中位数。

首次构建记录定位缓存在同步 API 中仍可占用约 239 ms；工程扫描已使用异步入口，避免在主线程执行这一段。其他使用同步 API 的维护调用没有在本次全部迁移。

### 输出与数据语义

- 从全新缓存重新处理全部 386 个 PSD：232 个成功，154 个无预览。232 个成功结果的内容哈希和尺寸与基线全部一致，零差异。耗时约 3.72 s，基线约 3.34 s；不把该阶段报告为加速。
- 普通 PDF：子进程与原 Worker 输出逐字节一致；同一进程复用后输出也一致。
- 原生回归覆盖记录幂等、更新后浏览顺序、精确批量删除、删除后恢复、保存/重载、旧分段读取、搜索同分及分段替换行为。
