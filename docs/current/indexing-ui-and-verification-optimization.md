# Indexing UI 与开发验证优化

> 状态：当前

## 已实施

- Manifest 建库批处理每 32 次修改保存一次，正常结束、取消和异常离开批处理时补齐尾部。独立预览调用仍等待保存。并发 load 合并；一次保存失败不会永久污染后续写入链。
- Manifest 排序、JSON 序列化，以及已有预览图的 Sharp 处理、矢量像素扫描和连通区域计算迁入同一条 Worker 执行通道；闲置 15 秒回收，失败或超时重建。保留原图像质量、尺寸、提供器版本与安全限制。
- 仍由主进程执行提供器选择、Windows Shell 预览、索引写入与原子文件发布。内置 PSD/PSB、KRA、SVG、TIFF 提取和 PDF/AI 首页面渲染均已接入 Worker；自定义外部提供器仍在主进程调度。
- scanning/indexing 进度通知每 100ms 合并一次，读取最新状态；状态切换和结束立即发送，清除旧定时通知。
- 工程规则独立保留在 `task/verification-flow`，本分支只处理 Indexing 卡顿。

- 大 Manifest 以 256 条一组传入 Worker，组间让出主线程；Worker 完成排序、序列化和临时文件写入，主进程只原子发布。
- 目录枚举改为异步流式读取，并每 128 项让出事件循环。失效来源检查改为最多 8 路异步 stat，权限/网络错误不作为已删除的证明；不可访问的根目录不执行缓存清理，原生记录删除失败时保留元数据以便重试。
- 预览/哈希完成后再次检查取消，防止停止后迟到的原生索引写入。Worker 闲置时保留错误观察器，避免闲置崩溃成为主进程未捕获错误。
- 准备流水线同样合并进度；Renderer 将同阶段连续进度作为可中断更新，开始/阶段切换/结束即时处理。

## 数据边界

Manifest 保留 v1 文件格式和原子 rename。一次崩溃可能留下不足 32 次尚未保存的派生预览元数据；下一轮需要重建这些派生项，因此这不是每个文件都已持久化的事务承诺。已完成或正常取消的批次会等待尾部保存。原始工程文件和原生索引格式不变。

## 待验收

- Windows 真正建库时采集主进程/Renderer 长任务和事件循环延迟，验证按钮响应与系统窗口拖动；本环境的功能测试不能替代该验收。
- 真实 NAS/工程混合素材下的吞吐、峰值内存、取消和异常恢复。
- Windows Shell 预览的耗时归因、外部提供器进程开销；真实 GPU/索引任务与 Renderer 的组合长测。
- 全项目测试映射、历史实验脚本和重复验证的引用审计；当前只统一源码入口及移除普通 push 的全量验证。

单 Worker 会增加部分运行时开销；本轮不宣称内存下降。本次不触发安装包构建或发布。

## 第一轮候选测量（后续改动前）

Linux、同一组 1,000 条合成 Manifest 记录、单轮原实现/候选对照：原子发布次数 1,000 → 32，耗时约 689 → 168ms；两边重新读取均为 1,000 条。此结果只说明该负载的写入与排序开销，不代表真实建库整体提速。相同矢量预览输入的最终 JPEG SHA256 一致。

构建后的 Worker 已单独加载运行，验证 Sharp 依赖定位与排序输出。源码功能回归覆盖批次尾部、保存失败重试、进度合并、生命周期通知、缓存复用和索引更新。

已知环境限制：Node 类型检查缺少 transformers/onnxruntime-node；Linux 外部预览提供器测试在原提交和候选均失败（Windows 可执行文件校验差异），跨盘测试仅 Windows 适用。没有把上述结果算作通过。

## 第二轮验证

浏览器合成桥向真实 React 工作区注入 10,001 条状态通知，设置切换完成约 305ms，结束后可返回素材准备页，无页面异常。此为 Renderer 压力检查，包含自动化和懒加载开销，不是实际原生建库或 Windows 窗口拖动验收。

新增回归覆盖取消发生在哈希期间不再写索引、权限失败不误删来源、10,000 条 Manifest 分块传递期间主事件循环持续执行。构建后的 Worker 验证包含 SVG/PDF 提取、图像解码和临时 Manifest 文件写入。

`image-preparation-pipeline` 集成测试另受本环境 Electron 二进制未安装阻塞，不计通过。Windows Shell 和外部提供器仍需目标平台复测。
