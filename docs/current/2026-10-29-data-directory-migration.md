# 应用数据目录迁移与局域网扩展边界

> 状态：当前  
> 更新日期：2026-10-29

## 已实现范围

- 设置的“数据与重置”和“索引与维护”提供应用数据位置、选择目标、重启迁移入口。目标为所选目录下新建的独立子目录，不覆盖已有文件夹。
- 迁移请求绑定选择目录的 renderer，短期有效且一次性使用，写入前显示原路径、新路径和原始素材不移动的确认。
- 使用既有正常退出、停止任务及刷盘流程。下次启动在业务数据库、索引、模型和浏览器 session 初始化前执行复制；成功后再次重启，在 ready 前绑定新 userData。
- 检查空间、目录嵌套及符号链接；未完成的数据事务或恢复日志会阻止迁移，先在原库完成恢复；复制时流式计算 SHA256，核对源、目标内容及整个源快照，最终再次校验目标文件。目标权限保护在复制业务数据之前执行。
- 切换引导文件之前保留原数据。取消、磁盘不足、连接变化、复制或校验失败均继续使用原根目录。未完成副本没有有效库描述文件，不能重新定位为正式库；不自动清理原目录或失败副本。
- 数据盘离线或库编号不匹配时阻止业务初始化，提供重新定位或退出，不静默创建空库。
- 视频数据默认跟随实际 userData，不再按旧目录清单大小选根。显式视频缓存环境变量覆盖仍保留，但启用覆盖时阻止整体迁移，避免遗留正在使用的数据。

## 数据与路径兼容

旧库在原位置增加稳定 libraryId，不重建素材 ID 或关系。应用数据位置引导文件在固定的 `%APPDATA%\siftory-storage-location.json`；根目录 `.siftory-library.json` 记录相同库编号及历史应用数据路径。保留的旧目录是静态副本，后续写入仅发生在当前目录。

数据库、WAL 等配套文件、JSONL、向量数值及模型载荷保持复制时的字节内容。历史内部路径在读取边界映射：视频帧清单、封面、缩略图、媒体工具、工程预览，以及视频帧/向量缓存的路径匹配。外部素材路径不参与映射。缓存加速索引可能因来源签名变化而刷新；这不等于重新运行模型生成向量。

映射记录随迁移累计，最多 64 个历史应用根目录。旧版本不会识别新的位置引导；回退前应记录版本与实际位置，避免在旧副本上继续写入后误认为数据仍同步。便携备份与独立全量备份规则继续适用。

## 为局域网共用预留的边界

- `StorageLocationService` 和迁移执行器独立于 Electron、renderer 和网络传输；将来可由唯一写入的主机服务调用。
- `storage-location` 共享合同提供稳定 libraryId，以及 libraryId/sourceId/relativePath 形式的素材定位合同。当前只实现 local 后端；这些类型不表示现有索引已经全面改为相对路径。
- 桌面 IPC 只负责授权、系统目录选择和重启。后续 LAN 客户端应按库/素材编号请求主机服务，由主机解析本地路径，不能直接共写 SQLite、JSONL 或索引文件。
- 本轮没有开放网络端口、启用 NAS 多写、实现远程后端，也没有把原始素材根目录跨盘后的批量重关联标为完成。

## 验证与边界

新增迁移回归覆盖真实 SQLite 收藏记录、JSONL、二进制向量及模型复制、取消、空间不足、源变化、目标损坏、链接防护、目标冲突、引导写入失败和离线重新定位。额外用移走旧根目录的夹具验证视频帧读取、工程预览和已有向量复用。Electron 适配器通过隔离对话框与退出接口验证，设置页通过实际 React 浏览器回归验证。

这些自动测试不替代真实 Windows 双盘、拔盘断电、超大图库或安装升级实测。发布前应使用副本进行整套数据换盘及重启验收；原始素材目录的批量重新关联仍需后续实现。
