# 批量删除崩溃触发路径修复与界面收敛

> 状态：当前
> 更新日期：2026-11-12

## 崩溃证据与修复范围

用户批量删除期间的 Windows 事件与本地转储指向 `sharp-win32-x64-0.35.5.node+0x39034`，异常为 `0xc0000409`，参数为 5（`FAST_FAIL_INVALID_ARG`）。这不是可由 JS 异常边界捕获的普通解码错误。

隔离 Node 子进程中，8 路并发向 sharp 传入大量不存在的图片路径，约 686ms 后以 3221226505 退出。使用同版 Electron 42.11.18 的隔离 Node 模式复验，旧路径方式同样退出；新方式正常完成 4,000 个缺失输入的错误处理。以上测试没有使用用户的原图或回收站文件。

这证明了可复现的触发路径，并不意味着已逐帧还原用户崩溃时的调用栈。转储中的栈内地址列表仅作为线索，未冒充带符号的展开调用栈。上游错误处理源码中的共享错误缓冲区是进一步归因线索，不将其写为已完全证实的具体竞态。

修复方式：应用内直接使用文件路径调用 sharp 的缩略图、嵌入元数据、DINO/CLIP 回退、主体、人脸、颜色及形状等入口，改为先用文件系统获取只读字节快照，再交给 sharp。缺失文件在进入原生解码前返回文件系统错误。一次调用内复用同一份快照，避免元数据与像素来自不同文件版本；批量候选循环按每张图片分别读取。

读取通过同一个文件句柄完成，按初始大小读取，校验读取前后的大小和修改时间，遇到截断、增长或读取失败则拒绝输入并关闭句柄。缩略图与 CLIP 原有文件大小限制继续生效。既有像素限制、解码参数、JPEG 恢复、搜索算法、图像质量和任务并发策略不变。

该修复不保证所有损坏格式都不会触发第三方原生库缺陷，也不替代完整进程隔离。没有升级或修改第三方二进制。

## 回归与代价

- 单独进程的 4,000 个缺失路径、空文件、目录、大小限制和读取中变更检查通过。
- JPEG、PNG、WebP、TIFF、AVIF：源文件删除后，快照仍可解码，编码缩略图字节与原路径流程一致。
- DINO/CLIP 的像素及张量等价、方向、透明度、JPEG 恢复、解码预算与缩略图相关回归通过。依赖未安装人脸/行人模型的推理测试保持跳过，不宣称完整模型矩阵验收。
- 24 张 800×600 生成噪声图片，JPEG/PNG/WebP，2 路并发，交替顺序、每方案 3 个新进程：处理耗时中位数 343.9 → 292.9ms；进程峰值 RSS 中位数约 94.6 → 108.3MiB。24 项输出哈希全部一致。
- RSS 增加约 13.7MiB 是压缩输入快照的代价；上述小数据集不代表真实图库或整个应用的性能结论，不宣称内存下降。

诊断与原始采样保留在被忽略的 `artifacts/crash-20261112/`，完整崩溃转储不随源码发布。

## 界面收敛

- 数据清理集中到“设置 → 数据与重置”的范围选择器：盘符/文件夹、文件夹索引层、全部图片派生数据。每种操作继续使用原有预览、范围和确认流程；没有把不同删除作用域混成同一后台操作。全库入口明确只作用于图片派生数据。
- 文件夹索引层选项跳转并展开维护页的既有高级工具，继续由用户选择路径和索引层。
- 按来源任务组件切换范围时保持挂载，不因界面切换中断现有任务或丢失预览。
- 图片、视频扫描可以从同一已登记目录列表选择根目录；保留原生文件夹浏览。只复制用户选中的扫描范围，不自动登记来源、不启动第二次来源扫描，也不合并不同数据存储的权威边界。
- 分步骤扫描和视频构建操作在高级模式内继续折叠，主要入口仍为“准备素材库”。
- 主题下拉框与配色预览合并为一个带当前主题名称的配色选择器；模式选择继续保留。

模拟 Electron 桥的浏览器检查已验证目录复用、分步骤折叠、主题选择、三种清理范围与文件夹工具跳转；没有执行真实删除。
