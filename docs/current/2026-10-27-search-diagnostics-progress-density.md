# 搜索诊断、真实进度与紧凑界面：第一批修复

> 状态：当前  
> 更新日期：2026-10-27

日期：2026-10-27（北京时间）。基于用户上传的 1.0.1-alpha.6 源码包；保持版本号，不宣称已经发布新版本。

## 已落地

- 图片页的快速、标准、精准查询增加诊断编号，后端记录开始、输入身份、阶段切换、候选来源与评分、结果、降级、异常和同步导致的丢弃。前端记录结果接收或过期丢弃，并可标记“结果不对”。查询参数、原生索引状态、源变更 epoch、向量索引代次与更新时间用于比较重启前后差异。
- 输入记录 SHA256、文件字节数、稳定性和格式。PNG/JPEG 可在有限头部读取中取得尺寸，其他格式标为未知；项目文件的预处理输入也有独立指纹。DINO 查询记录向量指纹及子进程实际报告的 Provider；无法取得 Provider 时明确为 unknown。
- 日志使用安装内稳定的 HMAC 路径标识，不记录素材原始路径、文件名、原图字节或完整向量。每阶段最多记录前 50 个候选，因此不在记录中不能直接证明不在完整候选集。
- 原生日志滚动为最多 5 个 4 MiB 文件，保留 14 天；写队列上限 128，异常不会阻断搜索，失败/丢弃计数可在诊断入口提示。指纹最多同时读取 2 个文件，单文件超过 64 MiB 时不生成完整指纹。重启后会修复未写完的末尾记录，再继续追加。
- “搜索诊断”中可以导出 JSON、清空、标记错误结果。默认不复制查询图；用户主动保存复现副本时，校验与搜索时的字节指纹相同。最多 4 份、单份最多 2 MiB、合计磁盘预算 8 MiB，超过 14 天清理；可选副本会包含在导出 JSON 的 base64 字段中。基础日志和副本合计预算不超过约 28 MiB（另有一个 32 字节身份密钥）。
- 活跃任务进度使用向下取一位小数，最多 99.9%，不再将 19,404/19,412 取整为 100%。扫描或流式输入仍开放时显示不确定进度，隐藏 ETA。准备流程显示阶段名称，不再将内部权重百分比作为确定的全库完成比例。
- 修复 CLIP 历史记录盖过活跃 DINO，以及同一全局进度被同时映射为两个模型后误标名称的问题。后端进度携带实际模型名和输入集合是否仍开放，任务卡显示成功、跳过、剩余和失败；有失败的终态明确提示。排队说明不再冒充当前文件，ETA 标为当前阶段估算。
- 图片与文字查询共享前端代次；清空、切换引擎或新查询后，旧响应不能覆盖新状态。引擎切换清理旧结果，避免用新模式标记旧结果。降级和查询失败在页面持续显示，结果原因不再把所有降级都误称为“模型未安装”。
- 压缩桌面页头，Alpha 提示默认收起且可展开；去掉图片查询区重复标题说明。已有索引状态缩为右对齐的一行，诊断入口默认收起并放在查询区下方。中等宽度首次打开默认收起导航，仍允许手动展开。

## 使用诊断

在“搜索 → 图片”进行查询，展开“搜索诊断”：

1. 如果结果不对，点击标记本次查询。
2. 如需保留当时输入，主动点击“保存本次查询副本用于复现”。输入已被替换、临时文件已删除、指纹不可用或大小超限时会失败；不要认为所有历史输入都已自动留存。
3. 导出诊断。导出包含有限历史记录及用户主动保存的副本，不自动上传。仅有指纹的记录不能恢复原始像素。
4. 对完全相同输入做精准、快速、精准、重启后精准的对照，尽量同时记录是否正在建库，并保留预期原图。
