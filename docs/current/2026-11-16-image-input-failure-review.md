# Alpha34：向量生成失败后的输入复核

> 状态：已交付 Alpha34 Windows 测试版，真实素材待验收
> 日期：2026-11-16

Alpha33 用户日志本轮记录 101 个 DINO 失败文件：72 个位于 Cargo 的 JPEG 测试/模糊测试语料目录，23 个触发像素上限，4 个 PNG 解码失败，2 个 BMP 不受当前解码器支持。单项失败此前会阻断整个素材库准备过程。不能把这些文件都当作模型/GPU 故障，也不能把所有失败一律隐藏。

## 行为

DINO/CLIP Worker 只在图片解码边界标记输入失败，模型加载、推理和向量验证错误不带此标记。一次向量生成结束前，主进程对至多 4096 个解码失败候选执行最终复核：最多四路异步读取，每个文件最多读取前 64 KiB，检查签名、JPEG 编码及精度、可识别格式的尺寸、文件稳定性，并结合原始解码错误判断是否适合当前解码器。

可确认的非图像/不支持签名、AppleDouble 辅助文件、12 位或算术 JPEG 等不支持的 JPEG、畸形/空文件头、超过已知模型像素限额的输入，以及已明确报告的图像负载解码拒绝，被归为 `skipped`。不为它们生成假向量、不增加成功数量。确认跳过项从失败计数移入跳过计数，原始素材不修改。没有明确证据的 `Unknown error`、未标记的错误、检查失败、丢失/无权限的文件仍保留失败。

文件头合法不能证明像素负载完整，故日志使用“当前解码器拒绝”等类别，不把所有负载失败认定为文件损坏。达到有界读取上限而无法解析完整 JPEG 头时不凭猜测跳过。保持既有像素与内存保护，不关闭 `limitInputPixels`。

GPU、ONNX/模型、推理、Tensor、进程、内存耗尽和向量写盘错误继续报错。复核日志无法持久化也不会显示为干净完成。复核受建库代际和取消状态约束，旧任务不得修改下一轮计数；保留流式输入关闭与持久化完成的原有完成屏障。

## 界面及日志

准备流程在确认输入跳过后继续执行其他模型和向量索引提交，完成提示为“素材库准备完成，部分文件已跳过，详情见扫描与预览日志。”，简洁和高级模式均可显示。模型阶段完成不等于每个原文件都有向量，跳过提示保留这一差异。

自动错误报告新增 `embedding-input` 阶段，严重性为 `skipped`，保存类别、模型、文件结构信息及原始解码原因；沿用默认路径脱敏和可选路径映射，按小批次持久化，防止日志队列溢出。多个模型处理同一文件会有多次尝试记录，应按匿名源 ID 区分唯一文件数。历史 `embedding_failures.jsonl` 不清空；本次确认跳过项不会再作为新错误追加到该文件，真实失败仍保留。

此次没有将整个 Cargo 目录自动排除，也没有扩大特殊 JPEG/BMP 的解码支持；实现的是用户要求的失败后复核与正确分类。修复输入或升级解码能力后可在后续建库重新检查，不建立永久黑名单。

## 验证及复测

新增测试覆盖特殊 JPEG、正常 JPEG 的未知错误、像素边界、BMP/AppleDouble/空头、PNG 负载失败、未标记错误、损坏头、丢失文件、部分头和取消。真实服务控制流程测试使用隔离的外部依赖，检查成功向量保留、失败转跳过、真 GPU/写盘/诊断失败保留、代际隔离及批量日志背压；不模拟 GPU 性能。

管线测试验证 DINO/CLIP 及索引提交可在有已确认跳过项时完成，未经确认的失败仍阻止 ready。浏览器检查使用真实 React 界面和 Renderer 采样、模拟 IPC，验证高级模式显示跳过提示并清除旧错误；不等同 Windows/GPU 实测。

本地核心关联测试、前端类型检查、修改文件 ESLint、构建图和前端/Electron 生产构建需通过。云依赖环境缺少 Transformers/ONNX，扩展运行的原有图像解码套件有六项依赖阻塞，全量主进程类型检查另有既有 Worker Host 类型错误；不得宣称全量检查通过。Windows 工作流新增输入复核测试及真实 RawImage 图像解码回归，完成后单独记录结果。

安装后用原目录正常准备素材库。结束后导出扫描与预览日志，可勾选本次会话路径；核对原 101 个文件是否被正确分类，以及是否仍有真正的模型/运行时错误。源文件尚未在云端运行，不能事先承诺 101 项全部变为跳过。完整旧 UI 回归与已有安装升级状态由发布证据单独列出。

## Alpha34 用户复测后的跟进（尚未打入已发布安装包）

用户 2026-11-16 13:33 左右的报告确认 91 项归为跳过：68 项不支持输入、6 项解码拒绝、17 项像素超限。DINO 最终仍有 10 项失败，不能宣称本问题完全解决。与上一轮文件清单比对，未进入跳过明细的候选为六份同名贴图和四个 JPEG 测试样本；其中六份贴图在本轮原生扫描中也报告像素超限。本轮逐项向量失败仍需最新 `embedding_failures.jsonl` 确认，不能仅凭历史原因推断本轮根因。

此次发现统一扫描报告只导出了跳过明细和最终失败总数，未包含复核未通过项的逐项错误。源码已补充：`logEmbeddingFailure` 同时写入统一报告的 `embedding:EMBEDDING_FAILED`，保留源 ID、原始原因、模型和解码阶段标记，沿用路径脱敏及可选映射。正常跳过项不写作错误，真实故障与未能确认的输入失败均保留。

对应核心测试现为 43 项，通过；新增用例确认复核不确定时逐项明细也会导出。这是源码跟进，已发布 Alpha34 安装包仍为上文固定源码 `0ccb1ae`，不包含此日志补丁；剩余十项的处理方式尚未变更。
