## 目标

在启动多类型 Qwen 推理前，先从现有视频库建立可复核的人工分类。原目标为八种 profile 每类至少10条，共80条可用样本；本轮经用户确认按现有素材继续，因此属于“部分覆盖基准”，不能写成完整八类验收。

## 启动

```powershell
npm.cmd run review:profiles
```

使用命令输出的完整本地地址。服务只监听`127.0.0.1`，地址包含随机访问令牌。

如果要在同一 Wi-Fi/局域网的手机上验收，使用显式局域网入口：

```powershell
npm.cmd run review:profiles:lan
```

在手机浏览器打开命令输出的“局域网”完整地址。电脑和手机必须处于同一局域网；地址中的随机令牌等同于本次验收密钥，不要发送给局域网外的人。

## 操作

1. 点击“播放中间20秒”。如果中间段是片头、广告或黑屏，可以直接拖动播放器查看主体内容。
2. 在八个类型按钮中选择一个。点击后立即原子保存，“未分类”视图会自动进入下一条。
3. 无法判断、损坏、内容不适合的候选点“无效/暂不适合”，不要强行归类。
4. 顶部每个类型显示`n/10`，八类均达到10条时才解锁下一阶段。
5. 可使用数字键`1`到`8`快速归类，空格播放目标片段，左右方向键切换候选。

## 候选覆盖

- 总候选：192条。
- 时长：短/中/长为152/32/8。
- 画面：竖屏/横屏/近方形为50/132/10。
- 音频：148条带音轨。
- 转写：3条已有转写。

候选是确定性分层抽样，不是模型生成的真值。弱建议只依据横竖屏、时长和文件弱提示，必须人工确认。

## 隐私与保存

- 默认入口只监听`127.0.0.1`；只有显式使用`review:profiles:lan`时才监听局域网。
- API、页面和匿名导出均不包含原始路径或文件名。
- 所有数据、视频和写入API在本机与局域网模式下都必须携带随机令牌。
- 视频只通过匿名ID和有界HTTP Range播放。
- 复核记录保存在 Media Search 私有语义目录的`semantic/reviews/video-profile-corpus-review.json`。
- 备注仅留在私有复核文件，不进入匿名样本导出。

## 本轮冻结的部分覆盖

人工处理84条候选，其中79条接受、5条跳过。过滤少于4张可用缓存帧的样本后，固定44条匿名推理计划：影视/动画10、短视频/Vlog 10、课程/教程/录屏10、游戏/直播7、通用4、监控/固定机位3；会议/访谈/播客和体育为0。

这44条可以验证当前已有六类素材的端到端流程，但以下缺口仍保留：

- 会议/访谈/播客与体育没有样本，不能给出结论。
- 游戏、通用与监控不足每类10条，只能报告实际样本数。
- 影视分类18条中有2条、课程21条中有7条、游戏14条中有7条因缓存帧不足未进入推理。

## Qwen语义复核

同一个验收服务新增第二阶段页面：

```text
http://127.0.0.1:4181/benchmark?token=<服务输出的令牌>
```

页面每5秒读取后台检查点，已生成的结果会自动进入“待复核”队列。操作规则：

1. 完整观看20秒验收片段，并核对右侧Qwen摘要、场景、事件、人物、物体、OCR和检索词。
2. 选择“像 / 部分像 / 不像”；数字键`1/2/3`可快速操作。
3. 单独标注幻觉程度和事件时间点准确性，必要时添加私有备注。
4. 每次操作立即原子保存到`semantic/reviews/video-profile-semantic-review.json`。
5. 匿名导出不含原路径、文件名或备注。页面显示的是“人工语义接受率/严格一致率”代理指标，不等同于正式召回率。
