# Alpha32：高位深 PSD 合成图预览

> 状态：已交付 Windows 测试版，真实素材待验收
> 更新日期：2026-11-14

Alpha31 用户错误日志中，166 个 PSD 的 Shell 预览获取失败，其中 153 个为 16 位、9 个为 32 位。日志只能证明现有内嵌 JPEG 与系统预览链未取得可用图像，不能据此判定文件损坏。此次针对这些文件补充独立合成图读取，不改动原始素材。

## 处理方式

优先使用已有内嵌 JPEG；未取得 JPEG 时，通过新的 `psd-composite-raster` Provider 读取文件末尾的合成图，最后保留独立进程中的 Shell 回退。支持 PSD/PSB、灰度/RGB、8/16/32 位及 Raw、PackBits RLE、ZIP、ZIP Prediction。32 位浮点颜色按线性光转换为显示值，透明度独立处理。

按区段长度跳过颜色信息、资源和图层树，不解析图层或完整读取大工程文件。Raw/RLE 按预览需要读取采样行；ZIP 流式解压并验证输出长度，直接采样到最长边 1024 的预览。计算在既有串行后台 Worker 执行，未新增依赖。源码运行与打包后的 Worker 均需通过实际提取检查。

源图每边最多 32768、最多一亿像素、预计合成数据最多 256 MiB；ZIP 输入最多 128 MiB，读取/解压有十秒预算。畸形行、越界段、截断与异常解压输出均拒绝。限制不能覆盖所有操作系统 I/O 等待，外层 Worker 的既有超时仍保留。

新增 Provider 改变失败缓存的链版本，因此原先失败的 PSD 在下次正常更新时重试，无需删除索引。成功的既有 Provider 缓存继续复用。

## 范围与限制

此次只优化 PSD/PSB 预览，不包含 WebP、DINO 102 张失败或 macOS 辅助文件过滤。暂不解码 CMYK、Lab、索引色、超过一个额外通道等组合；无合成图的文件仍依赖 Shell。预览采用采样、白底合成与浮点值裁剪，不作为 ICC 软打样或 HDR 输出。用户原始文件未上传，不能宣称真实目录的失败项已全部恢复。

## 验证

新增测试验证 Raw/RLE/ZIP/预测还原、位深、RGB 通道顺序、透明度、主线程心跳、畸形输入、解压上限、失败缓存重试，以及跳过超过 4 GiB 的 PSB 图层区段。最后一项使用 Linux 稀疏文件，Windows 跳过以避免生成实体巨型测试文件。

打包 Worker 检查必须生成真实的 16 位 PSD 预览；Windows 启动验收额外检查实际软件可提取 16/32 位 PSD，并确认使用新 Provider。旧版完整 UI 矩阵和安装升级状态单独报告。

本地完整预览测试中的外部转换器用例要求 `.exe`，云端 Node 可执行文件不带该扩展，属于现有平台限制；本地按范围排除这一用例，Windows 仍执行原测试。

本地结果：25 项新增 PSD 测试通过；首轮预览、错误采集和构建图相关检查共 86 项通过、1 项跳过（外部 `.exe` 用例按范围排除）。构建后的 Worker 实际 PSD 提取、完整前端及 Electron 资源构建、修改文件 ESLint、声明类型检查和构建隔离检查通过。完整主进程类型检查的既有环境限制未在本次宣称解决。

额外本地读取 psd-tools 的 10 个公开 PSD/PSB 样本（16/32 位 RGB、8 位灰度）均取得预览；样本来源：https://github.com/psd-tools/psd-tools/tree/main/tests/psd_files ，仅用于本地兼容性检查，未加入源码或安装包。

首轮 Windows 构建 `43572931805` 的原生与预览回归、编译、归档、实际 16/32 位 PSD 预览均通过，但随后的错误日志持久化检查超时，未发布。检查中另暴露 ZIP 流使用裸描述符导致文件句柄重复关闭警告；已在真实 Worker 中复现（旧实现重复八次出现八条警告），改为由 FileHandle 统一管理并通过新增回归。错误日志启动检查采用软件同盘的相对测试目录，保持真实扫描/IPC/持久化链，避免一次小目录验收触发整盘 USN 枚举，并断言扫描确实开始。新包须重新通过全部启动门禁。

## 安装后复测

保持原有目录与设置，正常更新素材库，不清空数据。检查之前失败的 `9. Damaged` 灰度笔刷及 32 位渲染 PSD 能否预览、搜索，同时观察界面响应。结束后导出“扫描与预览错误日志”；若需逐文件核对，在退出软件前勾选包含本次会话路径。若仍有失败，可提供其中一张原始 PSD 用于精确复现。
