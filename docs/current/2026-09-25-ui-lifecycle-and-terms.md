## 1. 已取得的证据

先前 UI 烟测的监听器增量曾为 53、106，超过原阈值 50。本轮先保留同一计数方法和阈值，加可选诊断，复现增量 58：当前主文档可枚举监听器始终 602，DOM 节点不变。第二轮记录到文件管理器持续对同一组 DOM 的 `onclick` 重复赋值，每批 12 个 button、36 个 div、5 个 span，合计 53；时钟另有每批 5 个。这些是对象和事件类型聚合，不记录函数、闭包、输入内容或本机目录名。

实际原因链已收敛为：烟测没有配置文件管理器路径，采用 `useFMStore` 的 C 盘默认目录；其递归目录大小统计在生命周期采样期间仍持续更新。React 19.2.8 在 onClick 属性更新时会重新设置 DOM onclick；当前 Chromium 的 JSEventHandler 在赋值时创建对象，Memory.getDOMCounters 的监听器数统计这类对象的构造/析构，并非仅当前已注册的回调总数。因此未结束的后台工作和包装对象回收时机干扰了原来的前后比较。此结论不等于证明所有模式均没有泄漏。

已将通用 UI 烟测初始化为独立临时样本目录，含 3 个文件、两级子目录、总计 896 字节。它不使用应用数据目录作为被统计目录，也不打开默认 C 盘。结果必须证明界面实际显示该目录、递归统计完整且总数为 896，退出前再次验证文件内容摘要。保留原面板循环、可见性循环及内存阈值；未关闭文件管理器功能或伪造统计结果。
