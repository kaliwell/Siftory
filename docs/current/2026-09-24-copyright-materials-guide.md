## 2. 源程序生成与追溯

`npm.cmd run copyright:source -- --output-dir <新的候选目录>` 从明确的 `electron/`、`shared/`、`src/`、`native/` 源码根目录生成候选。它不读取用户素材、模型权重、缓存、日志、依赖或测试夹具。原始文本保留空行和字符串内的空白；仅展示层把制表符展开为四个空格并为排版折行。单个原始行不会被截断到另一页。

顺序为 main、preload、Renderer 主入口和 App，然后按源码根目录及文件名稳定排列。显式排除第三方 `stb_image.h`、`stb_image_resize2.h`、构建目录、生成文件及声明文件；目录中的符号链接或联接点拒绝进入。此清单是登记候选范围，不认定其余源码全部为原创，最终需要权利人核对引入代码及贡献来源。

输出 `source-selection.json` 记录每个文件的字节摘要、物理代码行数、非空行数、版面折行数及每一展示行的文件、原行号和分段号。不能把版面行数直接写为整个软件的代码量。先对全部选取源码统一分页，正常页至少含 50 个非空原始源行，余数均衡分配到前部页；空白行和长行的展示续行不计入这 50 行。再取前后各连续 30 页；不超过 60 页时提供选取范围的全部页。范围仍须本人确认，不能因此宣称已证明覆盖完整原创程序。需要调整顺序或软件名称时，应重新生成整套材料，不手工拼接不连续片段。

源程序交存文件必须与最终审核候选的 SHA-256 一致。代码修改后旧鉴别材料立即成为历史候选；测试日志、源码清单与材料应重新绑定，不得把旧校验摘要用于新源码。

## 3. 文档鉴别材料

候选用户说明书依据[当前说明书](../reference/user-manual.md)生成，描述现有功能、模型准备条件、操作流程及数据保护。它不是商业宣传或未来功能方案。全文少于 60 页时提供全文；排版检查包括页眉、名称版本、页码、文本可读性和是否漏页。

登记参考规则来自[国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)第九至十三条。常规程序和文档鉴别材料按前后各连续 30 页准备；不足 60 页提供全部，通常源程序每页不少于 50 行、文档每页不少于 30 行。涉密内容需要依法选择适用的例外交存或封存方式，不通过任意涂改制造完整材料的外观。

## 4. 登记与分发授权分开处理

登记材料中标识自有创作范围，并单列第三方程序、模型权重、字体、工具和运行时。开源许可通常附有保留声明、提供许可证或其他义务；是否可用于当前分发方式须结合精确组件版本核对，不能仅凭许可证名称或下载仓库首页作结论。

第三方授权矩阵将分别列出许可证据、实际随包/外置状态、履约事项、缺失证据及可选方案。开发机本地安装不等于取得再分发许可；软著登记证书也不替代第三方许可。既有 `legal/license-decisions.json` 中未经真实决策的 pending 不会自动转为 approved。

本轮已完成[21 项运行组件与生产依赖许可矩阵](../../legal/copyright-research/license-matrix.md)、[个人登记办理与权利链核对](../../legal/copyright-research/registration-requirements.md)和[官方来源及本地证据索引](../../legal/copyright-research/sources.json)。研究记录区分当前上游说明与固定工件证据；后续代码优化产生的 Native 0.5.38 属本项目版本更新，其最终摘要以本轮实际构建及工程清单为准；阶段 Node 构建不替代 Electron 产物；本轮完整门禁和当前构建已单独绑定，PDF 与归档验证记录随候选包保存。研究时保留的旧版本哈希不冒充新版本产物哈希。

当前[随包许可补充载荷](../../legal/third-party/README.md)包含组件许可、专利与版权通知，具体文件和证据范围以同目录 manifest 为准；工程门禁按已审源树摘要核对实际载荷。3 个已识别 MPL 组件的源码已通过本地附件交付，获取说明及源码与实际原生组件摘要绑定。设置中已提供中英文第三方许可入口；后续在隔离副本中验证了正常 Electron 音频路径接受修改后的 FFmpeg。同次 UI 压力检查的监听器失败保留为历史证据，后续中英文各 600 次面板循环及 12 次可见性循环结果见[协议流程检查点](2026-09-25-end-user-terms-flow.md)，不能继续把该旧失败列为尚未定位的当前缺陷。实际源码附件、精确运行库来源与媒体测试范围见[LGPL 交付及运行库来源](../../legal/copyright-research/2026-09-25-lgpl-source-and-runtime-provenance.md)。这些工程证据不替代最终分发条款、生产签名或干净设备安装验收。

## 5. 提交前核对

1. 核对同一软件名称、版本、开发及发表日期，完成个人实名认证和权利来源证明准备。
2. 审阅源程序、说明书、来源清单及第三方排除范围；确认没有凭据、身份资料、客户数据或未经许可的代码片段。
3. 在中国版权保护中心官方系统填写并生成正式申请文件，按登录后的实际要求上传、签署及提交。候选信息表不能冒充正式申请表。
4. 签署与提交动作由本人对最终具体材料确认后进行；保存材料摘要、提交回执及申请号。

工程优化和本次验证见[执行清单](2026-09-24-copyright-readiness.md)。生产签名、正式性能、干净设备安装以及商业政策的剩余事项继续由[首版收尾 TODO](2026-09-11-release-completion-todo.md)跟踪，不以登记准备覆盖这些状态。
