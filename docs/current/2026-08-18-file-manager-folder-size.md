# 文件管理器文件夹大小显示与稳定排序

> 状态：当前  
> 更新日期：2026-08-19  
> 范围：文件管理器目录列表、大小排序、主进程目录统计、预加载 IPC 契约  
> 替代文档：无

## 完成内容

文件管理器现在会在列表、详细信息和图标视图中显示文件夹的递归逻辑大小。目录枚举仍先返回名称、类型和普通文件大小；包含不超过 64 个子文件夹的小目录会自动将全部子文件夹加入低并发统计队列，较大目录仍只统计当前滚动区域附近的项目，因此打开目录时不等待整棵目录树。

显示状态如下：

- `…`：大型目录中尚未进入可视区域附近的项目，等待按需统计。
- `排队中`：已经加入队列，正在等待主进程扫描名额。
- `≥ 大小`：正在扫描时持续显示当前累计逻辑大小；悬停可查看已扫描项目数。
- 普通大小值：递归统计完整。
- `≥ 大小`：到达 250,000 个目录项上限，或有子项不可访问，当前值是已统计到的下限。
- `—`：目录已离线、权限不足、路径失效或统计失败。

路径栏下方的大小汇总栏始终显示当前项目的“统计合计”：普通文件直接计入，正在扫描的文件夹按当前累计字节计入，已完成文件夹按递归大小计入。尚未结束时还会直接显示 `统计进度 已处理/总数`；已处理包括完整结果、不完整下限和读取失败，因此即使存在受保护目录，进度也能结束。只有当前显示项目已经全部加载，并且所有显示文件夹都得到完整结果时，综合大小才显示为精确值；否则显示 `统计合计 ≥ 大小`。因此翻页加载、滚动触发文件夹统计或切换“隐藏文件”时，综合值会安全地逐步更新，不会把未知部分当成 `0 B` 后误报为精确结果。

盘符或网络共享根目录会在同一汇总栏同时显示两种口径：左侧是 `统计合计`，右侧是 `磁盘已用 / 总容量 · 可用空间`。磁盘数值直接来自操作系统文件系统容量接口，而不是递归文件合计。这样 C 盘的磁盘值会包含 NTFS 元数据、系统保留、卷影副本、回收站以及当前用户无法枚举的受保护区域，与 Windows 磁盘容量口径一致；文件逻辑合计也保持可见，便于直接比较差额。

## 大小排序稳定性

大小列使用“用户点击时冻结”的显示快照。普通文件按目录枚举已经得到的字节数排序；文件夹只使用点击大小表头那一刻已经显示的递归字节数。之后到达的排队、扫描进度或完成事件仍会更新大小文本与合计，但不会在用户浏览、框选或键盘移动时把行重新排走。再次点击大小表头会显式获取一份新快照并切换升降序。

同一目录因排序变化而重新请求第一页时保留当前文件夹大小状态与冻结快照；路径切换、手动刷新、目录 Watcher 变化和窗格销毁会使旧快照失效。目录请求带代次票据，较早的导航、排序或 Watcher 响应不能覆盖最新列表；同一代次也不会重复提交下一页请求。服务端对普通文件使用确定性大小排序，对文件夹保留稳定的名称顺序，避免异步递归大小跨分页边界持续移动项目。

## 资源与生命周期约束

- Renderer 每个窗格最多提交 2 个并行请求，主进程跨全部窗格最多执行 2 个实际目录扫描。
- 子文件夹不超过 64 个时自动全部排队；超过该上限时，一个窗格只为可见区域附近的文件夹排队，避免创建无界扫描队列。
- 路径切换、刷新、窗格卸载和 Renderer 销毁都会取消旧请求。
- 完整结果缓存 60 秒，不完整结果缓存 10 秒，最多保留 512 项。一次扫描会复用整棵树中较浅的子目录统计，进入下一层时可直接命中缓存；子目录快照回调本身也限制为 512 项，避免超大目录产生无效缓存抖动。
- 文件操作或目录 Watcher 事件只失效与变更路径存在父子关系的缓存分支，不再清空所有无关目录结果；扫描期间发生变更时仍以代次标记阻止旧结果重新写入缓存。
- 统计使用 `lstat`，不跟随符号链接或目录联接，避免越界扫描和循环。
- 统计结果是文件逻辑字节之和，不代表 NTFS 实际占用空间、压缩后空间或稀疏文件物理占用。

## 接口

- `fm-get-folder-size`：读取一个文件夹的递归大小，携带窗格请求代次 ID。
- `fm-get-volume-space`：只允许查询盘符或共享根目录，通过 `statfs` 返回总容量、实际已用、空闲和当前用户可用空间；普通子目录请求会被拒绝。
- `fm-cancel-folder-size-requests`：取消该 Renderer 下同一代次的排队和运行请求。
- `fm:folder-size-progress`：只读进度事件，区分 `queued` / `scanning` 并返回已扫描项数和累计逻辑字节。
- Preload 仅暴露受控请求、取消和进度订阅接口，Renderer 不直接访问 Node 文件系统。

## 性能说明

首次统计速度主要由目录项数量决定，而不是总容量：每个普通文件至少需要一次元数据读取。机械硬盘随机访问、NAS 延迟、断盘重试、权限错误以及安全软件实时扫描都会进一步放大耗时。本实现通过可视区域按需调度、双层并发上限、进度反馈、子树缓存复用和按分支失效减少重复工作，但不会为了速度绕过权限、链接隔离或 250,000 项安全上限。盘符根目录无需递归扫描即可取得卷容量，但这个“实际已用空间”不能拆分成每个文件夹的精确占用。
