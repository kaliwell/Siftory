## 工具修复与已有验证

真实库基准原先传入空 sourcePaths，可能在读取组合快照前返回旧基础 generation，漏掉已提交增量。临时样本实际 base 2 + delta 3，旧基准只读到 2 条。新增只读快照发现，验证并读取当前已提交增量；损坏时拒绝执行，不默默回退旧基础快照。增加 CLIP 模型选项及活动库路径别名绑定。

GPU 图片基准仍使用旧文本协议，已改用现有二进制解码器并记录实际 Provider，避免漏结果或误称 GPU 测量。新增回归纳入 test:vector-ann 和 Windows CI。

已有快照及迁移路径相关测试 16/16、二进制基准协议测试 1/1 通过；相关修改的 ESLint、Prettier 和此前文档检查通过。用户叫停后未追加验证，未执行完整发布门禁。

## CPU 与真实图库

Windows x64，Node 24.22.1，Intel i7-12700H / 20 逻辑处理器 / 约 16 GB 内存。

DINO 原 F16 缺少完整元数据。本轮仅在测试目录将现有 JSONL 向量转换成 220,444 行、768 维的完整快照，没有运行模型重建图库，原 JSONL 完整 SHA256 在转换前后相同。新快照与原未提交 F16 字节不同，因此没有替换原缓存。CLIP 使用现有完整快照的私有副本（216,692 行、512 维）。

两种模型分别三轮、每轮 20 个查询，保持平均 Recall@50 in Top-200 ≥ 99.5%、最低 ≥ 96%、第一名一致门槛。

| DINO |    1 |          504.80 |          448.28 |     100% |     100% |
| DINO |    2 |          531.05 |          476.61 |     100% |     100% |
| DINO |    3 |          485.64 |          433.41 |     100% |     100% |

六轮分数、排序、第一名一致，测试快照的源文件哈希未变。DINO P50 降低约 10%–11%，CLIP 约 8%。这些是 ANN CPU 时间，不含推理、缩略图和 UI，不是受控空闲硬件的正式固定基线。此前游戏满载时的探索性结果仅保留在本地，不与本表混作同一负载。

## 模型推理与 GPU

同一批 32 张真实图片先复制并校验，测试目录中的图片保持只读。硬件 RTX 3050 Laptop / 4096 MiB，驱动 621.01；测量时已不再是此前游戏满载状态，没有关闭其他用户程序。

全部已完成候选的输入成功，DirectML 未回退 CPU。GPU batch 16、CPU batch 8/16 被现有内存策略跳过，没有绕过策略。DirectML batch 8 对 batch 4 最小向量余弦相似度四舍五入为 1，CLIP 最大逐维差约 0.00000221。

小样本包含冷启动和加载，不能据此宣称 GPU 必然更快。DirectML 适配器未显式固定；NVIDIA 显存采样为设备全局值，不能全部归因于模型。各阶段耗时、内存、显存及跳过原因见 JSON。CUDA 未验收。

## 实际应用完整查询：部分证据

在 OS 临时目录的私有配置运行实际 Electron 应用、React 界面、Native 索引和 DINO 检索。模型、索引、缓存复制到测试配置，只替换测试文件选择对话框返回值；查询仍经过正常 UI、IPC 和搜索服务。

- 4 次 GPU 意向查询实际 Provider 均为 DirectML，后端没有报告降级。
- 首次点击到结果提交约 3.18 秒，后续三次约 1.40–1.83 秒；后续三次可解码视口图片在约 1.61–1.93 秒出现。
- 首次查询在测试等待上限内没有解码的视口图片，缩略图验收不完整，不能把等待上限当作实际加载时间。
- 后续 4 次意向 CPU 查询实际仍为 DirectML，不能作为 CPU 完整链路基线。没有用意向标签冒充后端对比，用户叫停后不继续修复测试切换流程。
- JSON 保留模型批次指标、查询阶段、结果提交和图片时间。完整链路未通过全部要求；这不等同于已定位一个应用产品缺陷。
