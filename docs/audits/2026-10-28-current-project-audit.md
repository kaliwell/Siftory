## 待处理项

### A01 · P1：新增测试未进入默认测试链，verify 中断

`tests/global-hotkey.test.cjs` 没有加入 package.json 的测试命令。`tests/qa-toolchain-coverage.test.cjs:129` 的测试可达性检查因此失败。此次 verify 已执行到该门禁，共记录 539 次测试执行：537 通过、1 失败、1 跳过；后续测试链和该命令末尾的构建没有执行，不能宣称默认全量回归通过。

建议把新增测试纳入对应快捷键/窗口测试命令并确保默认 npm test 可达，再完整重跑。不要删除测试文件或跳过可达性门禁。

### A02 · P2：录入新组合时，没有隔离仍生效的原生全局快捷键

`src/components/GlobalHotkeyEditor.tsx` 只处理 renderer keydown，没有录入期的主进程状态；`electron/appCoreIpc.ts` 的显示/隐藏和退出回调持续注册。录入当前已生效的 Q 组合，或尝试 Shift+Escape 等内部保留组合时，原生动作仍有机会执行，不能依靠 renderer preventDefault 阻止它。

证据等级：代码路径确认。未向真实工作窗口发送退出组合；浏览器合成键盘事件不能证明 Windows 全局快捷键的原生行为。

建议增加由主进程管理的录入会话，在会话期间抑制本应用动作，失焦/结束时恢复，并在真实隔离 Electron 窗口验证。不要依靠短暂释放快捷键后必然能重新注册的假设。

### A03 · P2：启动读取配置时跳过内部冲突检查，可能报告错误注册成功

`electron/appCoreIpc.ts:418` 启动读取 global_hotkeys.json 后只校验语法，没有像保存 IPC 一样检查内部保留键。注册循环又把 isRegistered=true 直接视为当前功能已注册。

在独立临时目录将 visibility 配置为 Shift+Escape，主快捷键先注册后，退出条目也被标为 registered，但实际同一回调执行的是显示/隐藏。复现结果：`allMarkedRegistered=true`、`entriesSharingQuit=[toggle-primary, quit]`、`quitKeyInvokesVisibility=true`。

影响边界：正常设置页保存已有重复检查；本项针对手工编辑、历史迁移或异常配置恢复，不表示设置页可直接保存重复组合。

建议启动和保存共用语义校验；保留键冲突配置应回退默认组合并可见提示，注册状态应绑定具体动作所有权。

### A04 · P2：Tab 组合可被校验接受，但录入界面一律忽略

`shared/globalHotkey.ts` 支持 Ctrl+Tab 等组合；`GlobalHotkeyEditor.tsx:47` 对所有 Tab 直接返回，包含 Ctrl/Alt/Shift 修饰键。

实际 React 页面合成事件复现：录入前为 Ctrl+Shift+Alt+Q，发送 Ctrl+Tab 后仍是原值；发送 Ctrl+F9 后正确更新为 Ctrl+F9。证据见 record-tab-repro.json。

建议明确允许的组合范围：保留裸 Tab 的焦点导航；需要支持修饰 Tab 时，区分处理并测试。若不支持，应在校验、说明和录入提示中一致限制。
