## 四、本轮已实施整改

### 4.1 面板身份和窗口逻辑统一

- 在 `shared/ipc/app-core.ts` 建立 14 个面板的规范身份表，统一 `panelId`、DOM ID、可见性键、位置键和尺寸键。
- `DraggablePanel`、Settings 聚焦、Workspace Navigator、Linked Move 和 UI 冒烟共同读取同一份身份数据。
- 修复以下历史漂移：`duplicate-finder` / `dup-finder`、`media-search`、`batch-rename`、`calculator`。
- 修复 Duplicate Finder 联动移动读取不存在的 `duplicateFinderPos/Size`，现使用实际的 `dupFinderPos/Size`。
- UI 冒烟契约从只要求 8 个面板扩展为完整 14 个面板。

### 4.2 批量重命名时序与安全边界

- Renderer 在调用 `start` 前订阅进度，并在挂载时通过 `getProgress` / `getResults` 恢复已完成任务，避免快速任务在订阅前结束而永远停留在运行态。
- 增加启动错误恢复、默认尺寸、联动移动和锁定能力。
- IPC 对阈值的有限数值与 `(0, 1]` 范围、冲突策略枚举进行验证，并只构造受控请求对象。
- 服务对输入、修改和输出目录执行真实路径规范化，拒绝输出目录等于源目录或修改目录，避免直接覆盖输入树。
- 复制失败现在进入任务错误状态，不再被静默归类为“未匹配”。

### 4.3 媒体播放器导航信任

- 把播放器允许导航的判断抽成单一函数，对规范化后的实际播放器文件路径做精确匹配。
- IPC 来源校验和 `will-navigate` 共用该判断，移除可能接受同前缀伪造路径的 `startsWith` 判断。

### 4.4 生命周期与资源释放

- Duplicate Finder 和 Remote Terminal 隐藏时保留挂载，避免活动扫描或 SSH 会话因 UI 隐藏而丢失。
- Duplicate Finder 挂载后可恢复已完成结果，并带卸载保护。
- File Manager 卸载时取消待执行的 resize RAF。
- Image Search 通知计时器改为单实例更新并在卸载时清理，避免旧计时器提前清除新通知。
- Batch Rename 的进度监听在挂载期建立、卸载时释放。

### 4.5 文件管理器大小排序

- 同目录刷新保留文件夹大小状态；切换目录、显式刷新和 Watcher 失效时按边界重新计算。
- 点击“大小”排序时冻结当前显示值快照；后续文件夹大小异步计算只更新显示，不移动已经排好的行。

## 六、剩余风险与建议

### P1-1：Batch Rename 仍可能覆盖既有目标文件

证据：服务当前只用 `originUsed` 检查同一原图是否被多次使用；`copyFile(modPath, outputPath)` 默认会覆盖已经存在的目标文件，而结果中的 `conflicts` 仍固定为空。

影响：用户预先存在的输出可能被覆盖；取消或中途失败可能留下部分输出；`keep-best` 在扩展名不同的多对一场景中也可能留下前一次结果。

建议：先确定“覆盖、跳过、自动改名、失败”四种产品语义及取消后的部分结果策略，再以临时目录/阶段清单实施事务式提交。未经确认不应仅改成 `COPYFILE_EXCL`，因为这会改变现有覆盖行为。

### P1-2：部分模型伴随文件缺少完整性和原子下载

证据：隐式伴随文件下载仍使用 `response.arrayBuffer()` 整体读入内存并直接 `writeFileSync` 到最终路径；文件存在时会长期跳过。CLIP 主清单大多有哈希固定，但 DINO 和多语言隐式伴随文件没有全部进入精确的 `requiredFiles` 元数据。

影响：网络中断或磁盘异常可能留下长期复用的损坏文件；无下载上限会放大内存占用。固定 HTTPS 提交地址降低了远端替换风险，但不能替代本地哈希和原子落盘。

建议：把全部伴随文件加入版本化 manifest，固定大小与 SHA-256；流式写入同目录临时文件，完成哈希和大小验证后原子替换，并在启动校验时删除无效临时文件。

### P2-1：Batch Rename 的 Start IPC 等待整个任务完成

当前 IPC 对 `startBatchRename` 使用 `await`，任务 ID 不能立即作为启动响应返回。Renderer 的提前订阅和恢复已经避免 UI 丢进度，但服务权威层仍应在创建任务后立即返回 ID，再由事件/查询传递状态。

### P2-2：中心 Store 和大型面板职责过重

大文件和重复排布逻辑增加回归半径。建议按“布局、可见性、锁定、业务数据、持久化”建立表征测试后逐域拆分；不要同时改变状态格式、UI 结构和算法。

### P2-3：Renderer 主 chunk 超过提示线

这是优化机会，不是当前功能或性能失败。建议记录冷启动解析、首次交互和各 lazy panel 激活时间，以测量结果决定 vendor/shared chunk，而不是只按文件大小拆分。

### P3-1：纯 Node 全量测试仍有 ANN 预热告警

`vectorAnnWorkerHost.ts` 直接读取 `app.isPackaged`；部分纯 Node 测试没有完整 Electron `app`，因此会输出非致命预热告警。真实 Electron 与 ANN 专项测试通过。建议把 worker 路径解析做成可注入依赖或补齐统一 Electron 测试桩，不要在生产代码中启动长驻回退 worker。

### P3-2：可见性锁定存在死契约

`DraggablePanelProps` 声明了 `visibilityLocked` 和 `onToggleVisibilityLock`，各面板也计算并传入，但组件没有渲染或消费它们；对应 Store 状态也没有完整进入自动保存链。需要产品决定恢复 UI 入口还是删除死状态，本轮不改变 UX。
