# NekoSearch 分阶段整改验证

> 状态：已完成工程回归，发布验收未完成  
> 更新日期：2026-07-17  
> 范围：同步一致性、IPC 写入互斥、审核撤销、反馈门禁、索引边界、SQLite Catalog、素材分页性能和安装包归档  
> 审计来源：[NekoSearch 多维审计](../audits/2026-07-15-neko-search-multidimensional-audit.md)

## 结果摘要

四批整改解决了同步取消残留、审核撤销身份混淆、反馈默认启用、索引无预算解析、重复向量旧记录优先、参考图单中心、分类阈值未持久化、核心 JSONL 半提交、外部参考图失效和普通素材分页全量 Map 扫描等主要缺陷。当前估算工程健康度由 68/100 提升至 83/100；SQLite 关系表迁移、向量 worker/ANN 和固定准确率 A/B 仍是发布阻断项。

## 2026-07-17 样本搜索验证补充

本轮使用真实已审核 Category 做只读诊断：82 个去重正样本、98 个去重目标级负样本。旧模型只生成 `3 + 3` 个 prototype；算法 v2 改为最多保留 128 个正样本和 128 个负样本，并采用正样本 Top-2 支持与最近负样本 `0.65` 抑制。留一法区分 AUC 约为 `0.97`。

验证结论必须分开理解：

1. 工程回归：通过。`typecheck`、lint、format、26/26 NekoSearch 专项、IPC registration、preload contract 和六面板 UI smoke 均通过。
2. 样本内区分：改善。旧 prototype 压缩导致大部分审核数据未参与的问题已修复。
3. 真实全库主体准确率：未通过。用户验证仍出现背景、风格或通用类别相似但主体错误的结果。
4. DINO Hybrid：未验证且尚未实现。当前 DINO 为约 4GiB JSONL，缺少适合交互精排的随机访问缓存。

因此 `0.97` 不能作为发布准确率。下一轮基准必须使用与训练审核样本隔离的查询集和全库 hard negatives，至少报告 `Precision@20/50/100`、主体 Recall、Reject intrusion、P95 搜索延迟、峰值内存和 Renderer 响应。

## 真实库只读性能

当前资料库包含 180,034 个 active 素材。测试仅执行元数据载入和列表查询，没有改写真实分类、建议或聚类数据。

| 操作                  |     审计基线 |                      整改后 |
| --------------------- | -----------: | --------------------------: |
| 首次载入              |   约 948.9ms |                     827.8ms |
| 名称排序，首屏 100 条 | 493.4ms 平均 | 55.3ms 平均；暖机约 42-44ms |
| 大小排序，首屏 100 条 | 126.7ms 平均 |                  8.9ms 平均 |
| 最近更新，首屏 100 条 |  23.7ms 平均 |                 29.2ms 平均 |

上述真实库结果是第三批整改前的内存基线。第四批新增 SQLite 只读查询投影后，普通 Assets 分页不再扫描全部 active Map；分类、标签和未分类关系筛选仍保留内存回退，不能把本阶段理解为完整数据迁移。

## SQLite Catalog 合成基准

命令：`npm.cmd run benchmark:asset-catalog`。数据为临时目录生成的 180,000 条素材，不改写用户真实分类库。

| 操作                             |                                    结果 |
| -------------------------------- | --------------------------------------: |
| 首次构建投影                     | 2172.92ms；每 2048 行提交并让出事件循环 |
| 投影体积                         |           50.73 MiB（53,198,848 bytes） |
| 最近更新首屏 100 条              |                中位 2.45ms，最大 2.99ms |
| 名称排序 offset 90,000、100 条   |               中位 9.78ms，最大 10.07ms |
| 路径子串命中 750 条、返回 100 条 |              中位 30.89ms，最大 31.55ms |

实现边界：

1. `assets.jsonl`、`state.json` 和 `archived-assets.json` 仍是权威数据；`asset-catalog.sqlite` 是可删除、可按指纹重建的派生查询层。
2. 指纹与行数一致才启用 SQLite；校验、查询或重建失败时自动回退现有内存实现。
3. 归档少量素材使用 SQLite 增量更新；全量同步和手动素材变更在 JSONL 成功提交后重建投影。
4. 无关系筛选时，服务只为当前页组装分类/标签关系，不再为每次分页构造全库关系 Map。
5. 曾验证 FTS5 trigram：路径查询约 63ms 且首建增至约 14.9s，没有收益，已撤销；当前保留严格子串匹配。
