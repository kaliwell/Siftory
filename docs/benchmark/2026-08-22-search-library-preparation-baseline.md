## 结论

在同机、固定配置、三轮独立临时库条件下：

| 链路         | 工作流 ready P50 | P95 / 三轮最大值 | 主要阶段                                                           |
| ------------ | ---------------: | ---------------: | ------------------------------------------------------------------ |
| Image Search |      9,557.03 ms |      9,881.73 ms | CLIP 3,906.20 ms；DINO 2,837.41 ms；Native 扫描 1,344.50 ms        |
| Media Search |      5,644.59 ms |      5,678.75 ms | CLIP 2,435.53 ms；DINO 1,446.42 ms；抽帧与 Manifest 提交 444.45 ms |

图片当前简单模式在工作流 ready 后异步补全缩略图；后台缩略图排空 P50 为 2,923.63 ms，不计入“可搜索”里程碑。两条链路的 DINO/CLIP 仍占主要时间。视频逐帧 FFmpeg 启动的结构性问题仍存在，但这组短视频固定语料不能替代 `PREP-002` 的长视频、网络源和真实 A/B。

`workflowReadySignalMs` 表示主进程索引已经提交、前端工作流可以切换到 `Library ready` 的时点。无界面 runner 没有测量 React 提交到实际屏幕 paint 的延迟，报告没有把该延迟伪装成 0。

## 固定条件

| 项目       | 值                                                                           |
| ---------- | ---------------------------------------------------------------------------- |
| 系统       | Windows `10.0.22631`，x64                                                    |
| CPU / 内存 | Intel Core i7-12700H，20 逻辑处理器，16 GB RAM                               |
| Node       | `v24.16.0`                                                                   |
| Native     | `fast_scanner 0.5.30`                                                        |
| Embedding  | GPU，2 个请求 worker，上限 batch 固定为 4                                    |
| 图片流程   | 当前简单模式：扫描阶段不建缩略图，工作流 ready 后后台补全                    |
| 图片语料   | 固定 PxHere 子集前 16 图，31,187,640 bytes；语料快照 SHA-256 `bca815ef…bd21` |
| 视频语料   | runner 在计时前生成 CFR 12 秒、VFR 9 秒和截断损坏视频各 1 个                 |
| 视频抽帧   | 生产默认：本地 3 秒间隔、最多 3,600 帧、384 px；未用缩小范围换速度           |
| 重复次数   | 3；P95 使用 nearest-rank，因此三轮 P95 等于三轮最大值                        |

固定 batch 是可比较基线的一部分。首次诊断曾使用 `batch-size=0`，实际 batch 在不同轮次漂移为 4/8/16，CLIP 数值摘要随 batch 形状变化；该组数据被门禁拒绝，没有并入本基线。

## 正确性与安全门禁

| 项目         | 结果                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 图片数量     | 16 Native 记录、16 DINO、16 CLIP、16 ANN；三轮一致                      |
| 图片失败     | 扫描、DINO、CLIP 均为 0；后台缩略图 16/16 完成                          |
| 视频数量     | 3 个视频；7 个计划帧；6 个有效帧；DINO/CLIP 各 6；帧索引 12 行          |
| 视频预期失败 | 截断视频每轮产生 1 个 metadata、thumbnail 和 frame 失败；有效视频无失败 |
| 摘要         | Native、视频、帧、DINO、CLIP、ANN/帧索引的固定精度与位级摘要均三轮一致  |
| 源文件       | 每轮前后 size/mtime 快照一致                                            |
| 写入边界     | `userData`、媒体缓存、帧、向量和缩略图只写每轮验证过的临时目录          |
| 清理边界     | 只删除 `%TEMP%` 直属且带 runner 固定前缀的目录；不操作真实库            |
| 隐私         | 原始与聚合 JSON 的本机素材绝对路径检查为空                              |
