## 结论

本地视频默认抽帧已从“每个时间点启动一次 FFmpeg”改为“同一源文件按最多 12 帧、最多 30 秒跨度组成有界单输入批次”。固定 CFR 120 秒、VFR 90 秒和截断损坏输入的三轮 A/B 中，抽帧与原子 Manifest 提交 P50 从 `4,937.06 ms` 降至 `2,195.51 ms`，改善 `55.53%`；P95 从 `5,066.00 ms` 降至 `2,297.15 ms`。FFmpeg 抽帧进程启动数从 `71` 降至 `8`，超过任务要求的 20% 门槛。

挂载网络的稀疏采样没有套用该默认：现有单进程多输入 seek P50 为 `288.95 ms`，分组单输入为 `760.18 ms`，候选慢 `163.08%`，进程数也从 `3` 增至 `7`。因此网络继续使用原 `multi-input` 路径；候选保留为显式诊断模式，不默认启用。

## 实现边界

1. `electron/ffmpegService.ts` 新增有界单输入抽帧：一次打开一个视频，以 `split + trim` 为相邻时间点生成独立 JPEG；仍按旧路径的整秒 seek 语义、宽度和 JPEG 质量参数输出。
2. 每个输出先写入私有 `.partial.jpg`，只有 FFmpeg 成功退出且文件非空后才重命名到 Manifest 拥有的最终路径；失败、超时和取消均清理私有文件。
3. `electron/videoFrameService.ts` 按视频、批次数和时间跨度分组。本地批次失败时只对缺失帧调用原逐帧路径，已成功帧不重复生成；FFmpeg 不可用和取消不会触发无界重试。
4. Frame Manifest 继续在全部任务结束后一次提交，并改用带 PID 与 UUID 的私有临时文件，重命名失败时保留旧快照并清理临时文件。
5. `FLOATING_CLOCK_MEDIA_LOCAL_FRAME_MODE=legacy` 可强制使用旧本地路径，用于回归和现场回退；网络默认仍为 `multi-input`，只有显式选择 `single-input` 才运行候选。

采样间隔、时间点、`frameId`、Manifest 字段、JPEG 宽度、DINO/CLIP 输入集合、取消入口和原视频只读边界均未改变。没有迁移或改写用户现有帧、向量及索引格式。

## 固定 A/B 条件

| 项目     | 值                                                                         |
| -------- | -------------------------------------------------------------------------- |
| 语料     | runner 计时前生成 CFR 120 秒、VFR 90 秒、截断损坏 MP4 各 1 个              |
| 本地策略 | 生产默认 3 秒间隔；共计划 71 帧，70 成功、1 个预期损坏失败                 |
| 网络策略 | 生产默认 15 秒间隔；共计划 15 帧，14 成功、1 个预期损坏失败                |
| 输出     | JPEG，宽度 256 px；全部位于带固定前缀的隔离临时库                          |
| 次数     | 每种模式 3 轮，基线与候选交错运行；P95 为 nearest-rank，因此等于三轮最大值 |
| 安全     | 源快照运行前后相同；Manifest 行数、JPEG 可解码数和私有临时文件残留逐轮检查 |

## 三轮结果

| 场景     | 基线模式      | 候选模式       |         基线 P50 / P95 |         候选 P50 / P95 |     P50 变化 | FFmpeg 启动 P50 | 决策                    |
| -------- | ------------- | -------------- | ---------------------: | ---------------------: | -----------: | --------------: | ----------------------- |
| 本地     | `legacy`      | `single-input` | 4,937.06 / 5,066.00 ms | 2,195.51 / 2,297.15 ms |  改善 55.53% |          71 → 8 | 默认启用候选            |
| 挂载网络 | `multi-input` | `single-input` |     288.95 / 306.12 ms |     760.18 / 768.57 ms | 回退 163.08% |           3 → 7 | 保留基线，候选 deferred |

两种模式在各自场景的三轮帧摘要完全一致：本地 SHA-256 为 `f68a7c1…247d`，网络为 `df6783f5…1167`。摘要包含 `videoId`、计划时间点、记录宽度、状态和 JPEG 文件 SHA-256，因此同时约束帧数、状态和输出内容。

## 正确性、失败与安全验证

| 门禁               | 结果                                                                            |
| ------------------ | ------------------------------------------------------------------------------- |
| CFR/VFR 时间点     | 通过：1/4/7 秒的单输入输出与旧逐帧输出逐字节一致                                |
| 长视频与尾部覆盖   | 通过：120/90 秒固定语料按生产策略覆盖到尾部，计划数与 Manifest 一致             |
| 尺寸与可解码性     | 通过：每轮 70 个本地或 14 个网络成功输出均由 Sharp 解码为 256 px JPEG           |
| 损坏与部分失败回退 | 通过：正常帧保留，缺失帧只走旧路径；最终成功/失败状态与旧路径一致               |
| 运行中取消         | 通过：活动 FFmpeg 被终止，未完成记录可恢复，Manifest 可解析且无 `.partial` 残留 |
| Manifest 原子性    | 通过：注入重命名故障后旧 Manifest 字节不变，私有临时文件被清理                  |
| 源与真实库安全     | 通过：源文件快照不变，所有 A/B 输出仅写隔离临时目录，未写真实 `userData`        |

100 ms OS 采样器会漏掉旧路径中不足一个采样周期的短 FFmpeg 进程，所以其子进程 RSS/读写字节为 0 时只表示“未采到”，不能解释成真实零资源。资源门禁改用精确的进程事件计数、主进程 RSS 和保守的单批子进程上限：本地候选主进程 RSS P50 为 `127.82 MiB`，基线为 `128.41 MiB`；两者峰值活动 FFmpeg 均为 1，候选采到的子进程合计峰值约 `74.94 MiB`，低于 `512 MiB` 上限。

## 剩余风险与下一步

1. 当前固定语料验证了 MPEG-4 CFR/VFR、长片段和损坏输入；现场仍可用 `FLOATING_CLOCK_MEDIA_LOCAL_FRAME_MODE=legacy` 对特殊封装、硬件解码器或异常 GOP 做快速回退。
2. 网络源的延迟、缓存和带宽差异较大；本轮证据明确拒绝分组单输入默认值，后续只有在真实网络语料达到独立 20% 门槛时才重开该决策。
3. 本项只缩短抽帧阶段，没有把部分批次提前宣告为可搜索；CPU 抽帧与 GPU Embedding 的安全重叠属于后续 `PREP-003`。
