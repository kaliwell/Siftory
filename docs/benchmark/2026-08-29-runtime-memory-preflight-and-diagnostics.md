# 运行内存正式预检与诊断证据

日期：2026-08-29  
结论：实现与诊断继续；正式三轮验收暂缓

## 正式静默预检

执行 `npm.cmd run benchmark:memory:preflight`，完成 600,078 ms、73 点固定间隔采样。以下项目通过：

- 交流电供电，处理器 AC 上限 100%，Boost 模式 2。
- 最低可用物理内存 4,415,975,424 bytes，高于 4 GiB 门槛。
- Commit 峰值 14,610,456,576 / 31,814,365,184 bytes，比例 45.924%，低于 75%。
- CPU P95 5%，磁盘 P95 8%，残留产品进程 0。

预检未通过的项目：GPU 利用率 P95 为 45%，高于 10% 静默门槛；该历史运行当时还未接入已接受的 GPU baseline。工具按设计返回 `failed/incomplete`，没有放宽门槛，也没有启动正式重负载。后续已从三轮不可变固定硬件证据恢复 `1060 MiB` accepted GPU 基线，但不能追认这个受污染的历史窗口。

只读诊断显示 GPU 同时被 Windows 桌面、系统界面、硬件控制、通讯、WebView 和浏览器类进程使用。自动化没有关闭这些用户程序。

## 已通过的诊断场景

### UI 生命周期与缩略图 GPU

- 真实完成面板关闭/导航重开循环，递归进程树与 NVIDIA VRAM 采样同时有效。
- 8 张只读 PxHere 图片的隔离缩略图任务通过，源文件大小和时间戳未变。
- 整树 Private Bytes 峰值 2,679,103,488 bytes，退出后 259,616,768 bytes。
- 显存基线 819 MiB，峰值 1,405 MiB，退出后 817 MiB。

该结果证明任务执行和回收链路有效，不代替 10k 图片、1/2/8 请求档位的正式三轮矩阵。

### 8-profile 模型会话

- 1 次诊断重复覆盖 8 个固定 profile；每个 profile 都独立 `load/generate/dispose`，输出合法、sidecar 端口关闭、源文件未变化。
- 整树 Private Bytes 峰值 3,059,576,832 bytes，退出后 102,125,568 bytes。
- 显存基线 756 MiB，峰值 2,769 MiB，退出后 756 MiB。

整段 sawtooth 曲线不能用单一线性回归判断泄漏。编排器已改为按相同 profile 的三次重复比较峰值和销毁后谷值；正式门禁仍需 24 周期。

## 360 环境证据

`benchmark:memory:security-environment` 通过 Security Center、进程和服务只读查询记录脱敏证据：360 安全卫士状态为 `enabled/up-to-date`；相关实时防护和桌面服务在运行。服务版本已记录，报告不包含可执行文件路径，也没有关闭实时防护或添加排除项。

## 下一次正式运行条件

1. 用户自行关闭或静置非必要 GPU 应用，使 10 分钟窗口的 GPU P95 ≤10%。
2. 由正式入口自动验证 accepted GPU baseline，再按固定 AB/BA/AB 顺序执行三轮；不得用任意手填数替代接受证明。
3. 任何 identity、静默窗口或 360 采样离散异常都使整组结果无效。
