# 模型、运行时与文档确认规范

> 状态：当前  
> 版本：1.0  
> 更新日期：2026-07-22  
> 范围：所有接手、审计、实现、测试和文档任务  
> 替代文档：无

## 1. 目的

同一项目可能同时由 Codex、Kimi、Claude、Gemini 或人工开发者处理。模型名称、代理列表、任务状态和工具能力都只在各自运行时内有效，不能跨运行时推断。

任何执行者在读取 Todo、接手任务、启动代理或修改文件前，必须先确认：

1. 自己属于哪个模型和运行时。
2. Todo 中的代理属于哪个运行时。
3. 当前应采用哪组文档作为事实基线。
4. 是否存在其他执行者正在修改同一文件。

## 2. 开工前强制确认步骤

必须按顺序完成以下步骤；未完成时不得启动子代理或修改项目。

### 2.1 确认自身模型与运行时

1. 优先读取当前产品显示的模型名称、系统身份或运行时说明。
2. 只记录能够确认的粒度，例如 `Codex / GPT-5 系列`。
3. 如果精确小版本不可见，必须写“精确版本未公开”，不得根据语气、知识或工具名称猜测。
4. 用户提到另一个模型，不会改变当前执行者的身份。

### 2.2 确认代理归属

1. 代理列表只代表当前运行时创建和管理的代理。
2. `coder`、`reviewer`、`researcher` 等名称不是全局身份，引用时必须写成 `Kimi/coder`、`Codex/coder` 等带来源名称。
3. 用户说“某代理进行中”但未注明来源时，先确认来源，不得自行创建同名代理。
4. 当前运行时的代理查询结果不能用于判断其他运行时是否存在代理。
5. 外部运行时已有代理处理某项任务时，当前执行者不得重复启动同范围代理。

### 2.3 确认文档基线

1. 从 `docs/README.md` 进入，不从零散历史文档直接接手。
2. 按 README 的“当前基线”顺序阅读当前进度、实施基线、最新审计和专项方案。
3. 检查文档元数据的状态与更新时间；`历史快照`、`已替代` 不能覆盖 `当前` 文档。
4. 用当前代码、测试和真实运行结果复核文档结论。
5. 发现冲突时采用：当前代码与本次测试结果 > `current/` > 日期较新的审计 > 历史方案。

### 2.4 确认工作区与并发修改

1. 检查 Git 状态；若目录不是 Git 工作树，明确记录“无法可靠比较和回退”。
2. 检查目标文件的最近修改时间和正在运行的任务。
3. 无法确认改动归属时，不覆盖、不回退、不格式化相关文件。
4. 多个运行时共享同一目录时，同一时间一个文件只能有一个明确所有者。
5. 仓库已有稳定提交后，多模型并行写入必须按[Git 工作流与提交机制](git-workflow-and-commit-policy.md)使用独立物理 worktree；共享目录只允许交接期只读检查。

### 2.5 输出确认结果

开始任务前至少输出一次以下确认：

```text
执行身份：Codex / Kimi / Claude / Gemini / 人工
模型信息：已确认到的模型系列；精确版本未知时明确写未知
代理系统：当前运行时自己的代理机制
外部代理：名称、来源、负责范围；没有则写无
文档入口：docs/README.md
当前基线：本次实际读取的 current/audit/design 文档
工作区状态：Git/非 Git、已有改动、目标文件所有者
当前任务：只写本轮要处理的一项
```

确认结果只描述事实，不得把计划中的代理写成“正在运行”。

## 3. 各运行时的确认方式

### 3.1 Codex

1. 依据 Codex 会话的系统身份、模型选择界面或运行时说明确认身份。
2. 只使用 Codex 当前提供的协作/代理接口查看 Codex 代理树。
3. Codex 代理树中没有某代理，只能说明“Codex 树中没有”，不能说明 Kimi、Claude 或 Gemini 中没有。
4. 用户写 `Kimi/coder` 时，Codex 不得创建同名 Codex 代理代替它。

### 3.2 Kimi

1. 依据 Kimi 会话的模型标识、系统身份或 Kimi 原生任务界面确认身份。
2. 使用 Kimi 自己的 agent/task 状态作为 Kimi 代理事实源。
3. Kimi 的代理状态对 Codex 不可见；需要跨模型交接时，由用户或共享文档明确转述。

### 3.3 Claude

1. 依据 Claude 产品或运行时显示的模型标识确认身份。
2. 使用 Claude 当前环境提供的原生任务/代理机制。
3. 不把 Claude 的任务名称映射成 Codex 或 Kimi 的代理实例。

### 3.4 Gemini

1. 依据 Gemini 产品或运行时显示的模型标识确认身份。
2. 使用 Gemini 当前环境提供的原生会话/代理机制。
3. 不使用其他模型的代理查询结果判断 Gemini 任务状态。

### 3.5 身份无法确认的运行时

1. 明确写“当前模型/运行时未确认”。
2. 可以继续只读检查代码和文档。
3. 在用户确认前不得创建代理、接管外部代理任务或执行难以回退的修改。

## 4. Todo 与交接文档写法

跨模型 Todo 必须标注执行系统和所有者：

```markdown
| 顺序 | 任务                        | 执行系统 | 所有者     | 状态   |
| ---- | --------------------------- | -------- | ---------- | ------ |
| 1    | feedback 任务迁 worker      | Kimi     | Kimi/coder | 进行中 |
| 2    | stats/clusters 聚合计数优化 | 未分配   | 无         | 待做   |
```

禁止使用以下含糊写法：

```text
coder 子代理进行中
agent 已完成
让另一个模型继续
```

必须改为：

```text
Kimi/coder 正在处理 ①b；Codex 只做文档核对，不修改其目标文件。
```

## 5. 文档修改确认步骤

每次新增或修改文档前执行：

1. 确认自身模型、运行时和代理归属。
2. 确认目标文档状态为 `当前`、`草案`、`部分实施`、`历史快照` 或 `已替代`。
3. 检查是否已有更晚的同主题文档，避免重复建立事实入口。
4. 对照当前代码与测试，区分“已实现”“进行中”“计划中”和“未验证”。
5. 记录证据来源和验证命令；外部模型的口头状态必须标注来源。
6. 修改后检查 `docs/README.md`、相对链接、日期和替代关系。
7. 最后再次确认没有把一个运行时的代理状态写成另一个运行时的事实。

## 6. 冲突处理

1. 身份冲突：以当前会话的系统身份或产品模型标识为准。
2. 代理状态冲突：以该代理所属运行时的原生状态为准。
3. 文档与代码冲突：以当前代码和本次验证结果为准，并同步修正文档。
4. 并发改动冲突：停止写入，保留现场，由用户明确文件所有者。
5. 非 Git 工作区无法安全回退时，不做推测性撤销。
