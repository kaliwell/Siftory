# 开发验证流程

> 状态：当前

普通开发使用以下四个入口。Git Hooks 不执行建包、模型下载或全量测试。

| 命令                                           | 范围                                                                               |
| ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| `npm run verify:fast`                          | 暂存区敏感信息、禁止提交的运行产物、体积和空白检查；无需开发依赖                   |
| `npm run verify:changed`                       | 工作区已跟踪及未跟踪修改；按模块选择测试并对修改代码运行 ESLint                    |
| `npm run verify:changed -- --base=origin/main` | 比较基线到当前 HEAD 的已提交修改                                                   |
| `npm run verify:ci`                            | 完整源码质量检查；保留分层、安全、契约和类型校验                                   |
| `npm run verify:release`                       | 完整测试与关键覆盖率，加上现有安装包许可证、资源、归档及启动验证；不自动生成安装包 |

未知修改或共享契约修改不会静默跳过，而是回退至 CI 检查。新增模块时应补充 `scripts/verify.cjs` 的测试映射。当前已映射工程预览、缩略图、设置、导航、素材库、视频及 Git 规则；其余模块仍保守回退。`npm run verify:changed -- --plan` 只展示测试计划，不执行检查。

pre-commit 只运行 fast，扫描实际暂存内容；commit-msg 只检查简洁标题。格式为 `fix: 描述` 或 `fix(scope): 描述`，无需 AI 执行者元数据。pre-push 仅检查新增提交标题，不创建临时验证工作树、不跑全量测试。旧 snapshot 验证器保留用于显式检查和受控发布；不属于普通提交路径。

模块行数预算只警告。跨层依赖、无法解析的引用、共享依赖环及构建入口隔离仍是错误。没有为了减少耗时关闭安全或数据完整性检查。

每一步的退出状态和耗时写入忽略提交的 `artifacts/verification/timing.jsonl`。通过统一入口运行才能获得这些统计；历史直接调用脚本不会自动获得计时。`node scripts/verify.cjs timings` 按累计耗时排序，并区分同一次验证中的重复调用和不同次验证。嵌套命令耗时包含其子项，不应相加解释为总耗时。

`ci:verify:source` 是 `verify:ci` 的兼容别名，避免维护两套源码质量命令。CI 保留原有独立 native、浏览器及性能检查。CI 合并 workspace/core 两个测试清单并去重，保留全部原测试文件；取消单独再次执行 core 清单。原发布全量测试和关键覆盖率保留。五个无 npm/CI/脚本引用的历史实验驱动已归档至 `scripts/experiments/2026-11-07/`，不再混在普通开发脚本中。
