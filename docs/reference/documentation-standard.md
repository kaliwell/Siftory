# Siftory（寻藏）文档规范

> 状态：有效  
> 版本：1.1  
> 更新日期：2026-07-22

## 0. 修改文档前的身份与基线确认

所有文档工作开始前，必须先执行[模型、运行时与文档确认规范](model-runtime-and-document-confirmation.md)：

1. 确认当前执行者的模型和运行时，未知的精确版本不得猜测。
2. 确认代理所属系统；代理名称必须带来源，例如 `Kimi/coder`、`Codex/coder`。
3. 从 `docs/README.md` 确认当前文档基线，不直接沿用历史 Todo。
4. 用当前代码、测试和运行结果复核“已完成”“进行中”和“未验证”。
5. 确认工作区状态与目标文件所有者，避免多个模型同时修改同一文件。

交接或 Todo 涉及多个模型时，必须记录“执行系统”和“所有者”字段。当前运行时不得用自己的代理列表推断其他运行时的代理状态。

所有“已完成”记录还必须遵循[Git 工作流与提交机制](git-workflow-and-commit-policy.md)，写明对应任务、提交边界和实际验证结果。首次 Git 基线形成前，必须明确标注“未提交现场”，不得伪造提交编号。

## 1. 文件命名

人工维护文档使用小写 kebab-case：

```text
YYYY-MM-DD-scope-document-type.md
```

示例：

```text
2026-07-12-optimization-handoff.md
2026-06-22-security-cve-audit.md
2026-07-09-neko-search-classification-plan.md
```

没有明确日期且长期维护的参考文档可以省略日期，例如 `ipc-capability-matrix.md`。

Benchmark 脚本生成的 JSON/JSONL 文件保持脚本约定，不进行人工重命名。

## 2. 文档状态

文档开头必须标注下列状态之一：

| 状态       | 含义                                   |
| ---------- | -------------------------------------- |
| `当前`     | 当前实现和决策的有效依据               |
| `草案`     | 尚未批准或尚未实施                     |
| `部分实施` | 已落地一部分，正文必须列出剩余项       |
| `历史快照` | 只代表指定日期，不再作为当前依据       |
| `已替代`   | 已有新的文档或实现取代，必须给出新入口 |

推荐元数据格式：

```markdown
# 文档标题

> 状态：当前  
> 更新日期：YYYY-MM-DD  
> 范围：模块或目录  
> 替代文档：无
```

## 3. 标准结构

审计文档至少包含：

1. 目的与范围。
2. 当前结论。
3. 证据与验证命令。
4. 问题清单，包含严重度、影响和文件位置。
5. 已完成修复。
6. 剩余风险与下一步。

功能方案至少包含：

1. 目标与非目标。
2. 当前能力复用。
3. 架构和数据流。
4. 数据结构与 IPC 契约。
5. UI 与状态设计。
6. 性能、安全和失败恢复。
7. 实施阶段与验收标准。

交接文档至少包含：

1. 当前状态。
2. 已完成与未完成。
3. 关键文件入口。
4. 数据与模型位置。
5. 已知问题和禁止重复尝试的方案。
6. 验证命令。
7. 下一步优先级。

## 4. 可读性规则

1. 一个文档只有一个一级标题。
2. 标题层级按 `#`、`##`、`###` 顺序使用，不跳级。
3. 长文档在开头提供目录或快速入口。
4. 状态、结论和下一步放在正文前部，详细日志放在后部。
5. 表格只用于稳定的对比数据；过程说明使用编号列表。
6. 命令、文件、IPC channel 和代码标识使用反引号。
7. 验证状态统一使用：`通过`、`失败`、`部分通过`、`未验证`。
8. 不把推测写成事实；推测必须标记依据和验证方法。

## 5. 日期与版本

1. 文件名日期表示文档首次形成基线的日期。
2. 后续追加更新在元数据和变更记录中写明实际日期。
3. 文件名版本必须与正文版本一致。
4. 方案发生不兼容变化时新建版本；普通修订更新原文件。

## 6. 链接与归档

1. 仓库文档使用相对 Markdown 链接。
2. 文中代码路径从仓库根目录开始，例如 `electron/main.ts`。
3. 移动文件后同步替换所有 `docs/...` 引用。
4. 历史审计移入 `audits/` 或 `history/`，不删除原始证据。
5. `docs/README.md` 必须始终指向最新当前基线。

## 7. 验证记录模板

```markdown
## 验证

| 项目       | 命令                    | 结果             |
| ---------- | ----------------------- | ---------------- |
| TypeScript | `npm.cmd run typecheck` | 通过             |
| Lint       | `npm.cmd run lint`      | 通过             |
| 专项测试   | `npm.cmd run test:...`  | 21/21 通过       |
| 构建       | `npm.cmd run build`     | 未验证：说明原因 |
```

验证失败时必须保留错误摘要，不得只写“有问题”。
